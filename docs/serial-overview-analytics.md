# 班组数据分析与流水号台账（2026-09-12）

本次仅更新本地演示，不发布服务器、不清理或重新导入业务数据。正式数据库仍为 MySQL；当前本地演示沿用隔离 SQLite。沿用 Vue 3、Element Plus 和 ECharts，不引入另一套组件库。

## 页面入口

侧边栏仍为两级：班组 → 库房 / 轧制 / 退火 / 研磨 / 线切割 / 雕刻 / 电镀 / 检验。班组工作台内将下列内容拆成独立页面，各有可直接访问和刷新的地址，不增加第三级侧栏。

| 页面 | 内容 | 地址示例 |
| --- | --- | --- |
| 数据分析 | 六张班组图表、统计周期和单位、更多往来分析；不放台账表格 | `/team-workspaces/1` |
| 流水号台账 | 一行一个流水号、基本信息和完整余额；批次放进详情 | `/team-workspaces/1?tab=serials` |
| 材质归类 | 按材质的库存汇总表及紧凑操作区（2026-09-13 移除重复图和汇总卡） | `/team-workspaces/1?tab=materials` |

其他待接收、已接收物料、出库记录、丢失记录以及库房入库入口保留。班组长仍只能办理本班业务，管理员业务只读。

数据分析页点柱条、扇区或折线数据点，会进入带条件的流水号台账；浏览器返回可回到图表页。统计单位、周期和台账筛选、页码由地址保存。台账也可直接搜索或通过“分析筛选”选择条件，不依赖鼠标点击图表。

## 六张图的口径

图表以服务端全班组数据统计，不从当前 20 条列表推算。件数与重量可切换；流转和丢失支持近 7 天、近 30 天。

| 图表 | 统计内容 |
| --- | --- |
| 收发趋势 | 以接收/出库确认时间统计每天实际交接件数、重量；不是登记量或生产产量 |
| 流水号库存排行 | 当前账面结存前 10 个流水号，按所选件数或重量排序 |
| 物料类型构成 | 成品、半成品、余料、废品等当前结存构成；不是材质分类 |
| 库存停留时长 | 剩余来源批次自接收后的时长：不足 1 天、1–3 天、3–7 天、7 天及以上 |
| 待交接时长 | 待本班接收和待转出确认分开统计，按转料登记时间计算等待时长 |
| 丢失情况 | 已登记丢失的每日趋势，可切换流水号丢失排行；不把转废当作丢失 |

库存停留按尚有余额的原始来料批次计算。一个流水号追加新来料，不会把同流水号的老料停留时间重置。

“更多分析”展示接收来源、转出去向。库房手工入库、库房对外出库、检验发货分别使用独立类别，不伪造内部班组。材质归类页点击材质名称，可跳到流水号筛选结果。

每日边界使用工厂时区转换后的 UTC 范围；当前配置为亚洲时区。库存、待接收及待转出均为当前状态，不会因选择近 7 天而遗漏旧库存。近期选择只影响收发、丢失及往来事件。

## 流水号台账与详情

- 台账展示流水号、材质和转料规格、物料类型、当前结存、当前可用、待接收、待转出确认、最近动态。
- 同一流水号多次转入转出只占一行，数据库先按流水号汇总，再分页。默认每页 20 条，支持 50、100 条；宽表内部滚动，分页栏不随表格内容滚走。
- 结存 = 累计已接收 − 已确认转出 − 已登记丢失；可用 = 结存 − 待转出占用。待接收不计入结存。
- 图表和材质筛选用于选择“哪些流水号符合条件”。列表始终显示这些流水号的完整余额，而不是只展示匹配批次的局部余额，页面明确标注这一点。
- 不将成品件数等单据描述字段重复相加。同流水号的不同批次字段不一致时显示“多规格”“多类型”或“多值，见批次明细”，不擅自选最后一张单作为真实值。
- 点流水号或“详情”打开抽屉：基本单据信息、结存/可用/丢失，以及来源余量、转入明细、转出明细、丢失记录。四类明细均支持分页。
- 明细按交接行列出，一个 CK 整批可能包含多条物料行；不会把交接行数冒充整批数。点 CK 打开已有整批详情和条码；独立 TL 打开原单详情。
- 在明细中完成已有转料操作后，重新读取详情、台账及班组余额。没有新增录入、自动确认或管理员代操作权限。

空数据展示空状态；接口失败展示错误和重试，不补造零数据或虚构产量。当前演示数据集中在同一天，因此趋势暂时以一天为主，系统不填造历史波动。

## 接口及验证

新增只读接口：

- `GET /api/team-materials/{team_id}/analytics?days=7|30&metric=quantity|weight`
- `GET /api/team-materials/{team_id}/serials`：流水号、材质、类型、停留、等待、收发/丢失事件、往来筛选及分页。
- 现有库存和丢失列表增加精确 `serial_no` 筛选，供流水号详情使用。

使用既有台账余额查询和班组、来源、流水号索引，未修改数据库结构或执行迁移。MySQL 生产性能验收仍需在部署环境进行，本地 SQLite 响应时间不作为 MySQL 性能证明。

本次后端完整测试 132 项通过，前端完整测试 265 项通过，类型检查和生产构建通过。前端构建保留 ECharts 所在工作台分包超过 500 KB 的提示；后端有既有 AnyIO 弃用警告。测试包含多来源同流水号汇总、不重复扣减、混合元数据、唯一流水号分页、来源停留时长、确认日期及时区、权限与参数校验、图表跳转、返回及页面分离。
