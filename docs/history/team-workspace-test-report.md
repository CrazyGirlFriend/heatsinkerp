# 班组工作台与库房分类验收

日期：2026-09-06。业务口径见 [一期物料流转口径](../phase-1-material-transfer.md)，操作说明见 [一期用户使用说明](../phase-1-user-guide.md)。

本文保留上一轮动态工作台及撤回限制的历史验收事实，不代表最终八班组台账。用户随后确认的五页签、批量出库和丢失功能见 [新台账验收记录](../team-material-stock-test-report.md)。

## 1. 交付范围

- 启用班组目录驱动导航及 `/team-workspaces/:teamId` 页面；复用转料页面，不复制十套页面代码。
- `team_id` 与 `direction=all|outgoing|incoming` 控制查询范围，和其他筛选条件取交集；分页总数与状态统计使用同一范围。
- 班组长普通登录默认进入账号绑定班组；管理员保持全局只读业务入口。切换页面不赋予跨班组写权限。
- 物料类型增加 `semi_finished`（半成品），与 `semi_finished_surplus`（半成品余料）分别保存。
- 转入库房新单及接收方/类型修改须分类，`notes` 在该场景展示为入库说明。历史空类型允许确认，不伪造回填。
- 返回班组当前 `kind`，名称/编码仍使用单据快照；有历史引用的班组类型保护不变。

## 2. 当前配置核对

线上仅执行只读核对：15 个启用班组，包括库房、扎板、退火、研磨、线切割、雕刻、电镀、检验、发货、转废 10 个实际班组，以及下料班、机加工班、表面处理班、质检班、包装班 5 个演示班组。实际班组尚无绑定班组长，已有 5 个班组账号绑定演示班组。本轮没有自动建号、改绑真实账号或删除演示班组。

## 3. 后端验证

`backend/tests/test_material_transfers.py` 新增以下回归场景：

| 场景 | 核对内容 |
|---|---|
| 工作台范围 | 双向/发出/接收集合，排除无关班组；保留全局读权限 |
| 分页及状态数 | 每页记录、总数和三种状态数量都在相同班组方向内 |
| 条件交集 | 搜索字段、精确匹配、类型、双方班组、状态组合及矛盾条件为空 |
| 参数边界 | team_id 非正/非整数、未知 direction、无 team_id 的单向范围返回 422，不存在班组返回 404 |
| 动态目录 | 管理员排序/改名、新班组无账号也出现、停用消失 |
| 账号重绑 | 现有会话读取最新归属，发起方按新绑定自动确定，TEAM 不能创建班组 |
| 库房分类 | 空类型拒绝、新半成品可创建、入库说明保存及审计、分类修改可追溯 |
| 接收与锁定 | 库房账号整批确认，之后发起方不能改说明 |
| 修改去向 | 普通班组转库房须分类；切回普通班组响应 kind 立即一致 |
| 历史兼容 | 原空分类库房记录可幂等重试、仅修改备注和确认，不补造分类 |

首次新增用例中两处错误地尝试在班组已有历史引用后改变 kind，触发了既有 409 保护；已修正测试夹具，未放宽生产保护。库房两个用例重新运行全部通过（26.26 秒）。
