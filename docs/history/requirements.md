# 热沉工序流转管理系统历史需求基线

> 注意：本文记录旧版工艺、工单和报工方案，仅用于历史兼容与演进追溯。2026-09-06 起，一期实施以 [一期物料流转口径](../phase-1-material-transfer.md) 为准：不管理工艺、工单、报工或产量，管理员只维护班组和班组长，班组长直接发起与确认班组间整批转料。

## 1. 已确认业务口径

- 一个产品对应一条有序的工艺路线。
- 工艺路线由若干工序组成，并明确每道工序的前后顺序。
- 工单下达时取得当时有效的产品工艺路线，并生成该工单自己的工序快照。
- “上序”和“下序”是相邻两道工序的相对关系，不是固定部门。
- 工单按快照中的工序顺序逐步推进；最后一道工序完成后，工单结束。
- 流转记录表是一张工单全生命周期总表，一行代表一个工单。
- 点开工单可以查看下单、工艺制作、工艺单打印、各工序报工/投料、下序接收/入库和完成等历史。

## 2. 条形码与扫码枪

- 条形码内容等于“本次转料批次号”，不再等于工单号或流水号。
- 每次实际提交转料都生成一个持久化、唯一的转料批次号；同一工单和流水号可以有多个转料批次。
- 条码制式采用 Code 128，原样编码转料批次号。
- 蓝牙扫码枪按 HID 键盘使用：扫描后向当前输入框输入转料批次号并发送回车。
- 前端不调用摄像头、蓝牙或厂商 SDK；扫码后按批次号唯一定位该次转料和待接收信息。
- 流水号用于从公司主系统取得订单或工件信息，不代表某一次转料。
- 同一个扫码提交必须支持幂等，避免设备重复回车或网络重试产生重复业务记录。

## 3. 关键状态规则

- 产品工艺模板修改后，不影响已经下达的工单工序快照。
- 当前工序可加工数量来自已接收的上序数量；不必等待上序整单完成。
- 上序可以分批报工，也可以把报工结果拆成多次实际转料；每次转料有独立批次号和条形码。
- 相邻下序班组扫描具体转料批次后分次接收，未接收余量继续留在该批次待交接；多个工序可以同时有在制数量。
- 某转料批次发生任何接收或关联异常后锁定，禁止直接修改和删除。
- 当前版本不开放已锁定记录的撤销/冲销；未来纠错审批需要单独确认并实现。
- 工单当前状态、当前工序和总进度由工单工序状态汇总生成，不允许手工随意填写。

## 4. 账号、角色与班组

- 系统至少包含“管理员”和“班组账号”两类角色。
- 班组属于管理员维护的基础资料，管理员可以新增、修改、停用班组。
- 管理员创建或编辑账号时选择账号角色。
- 班组账号必须绑定一个有效班组；管理员账号可以不绑定班组。
- 产品工艺路线中的每道工序可以指定负责班组。
- 工单下达时，工序快照同时保存当时的负责班组，避免以后调整工艺或班组影响历史工单。
- 班组账号只能加工本班工序、接收交给本班的上序批次；管理员可管理及代操作，但同样受数量和已锁定记录规则约束。
- 作业录入从具体班组工作页进入。班组账号的录入班组由账号绑定关系锁定，不能通过网址参数切换；管理员可从具体生产班组进入并代操作该班工序。
- 报工、接收/入库和打印的操作账号及班组从当前登录身份取得，不接受前端自由填写操作人。
- 所有业务事件同时记录用户标识、账号名称和操作时所属班组。

## 5. 打印规则

- 工艺单用于整张生产任务，可显示工单号和流水号；转料单用于一次具体转料。
- 转料单必须包含转料批次号及其 Code 128 条形码，条形码不再编码工单号。
- 当前默认打印版式为 A4 上下双联，上联“存根联”、下联“随货联”，两联均显示批次条码、流水号、上下序、数量、重量、物料明细、分钟级时间和签字位。
- 业务打印时间记录并展示到分钟，格式为 `YYYY-MM-DD HH:mm`。
- 保存首次打印时间、最近打印时间、打印次数、打印人员和每次补打历史；转料单打印记录关联具体转料批次。
- 补打不得覆盖首次打印记录。

## 6. 第一版页面

- 流转记录总表：当前状态、当前工序、工序进度、最后操作时间及筛选查询。
- 工单详情：工单信息、工序路线、各工序状态和全生命周期时间线。
- 产品与工艺管理：为产品维护有顺序且可版本化的工艺路线。
- 工单管理：下单并生成工序快照。
- 班组作业：按班组查看工单产量与待办，并从具体工单进入报工、投料、下序接收或异常登记。
- 班组扫码接料：扫码枪输入转料批次号并回车，直接加载本次转料，校验账号绑定班组及目标工序后执行接收。
- 打印记录：首次打印和补打查询。
- 登录：账号密码登录并加载角色与班组信息。
- 班组管理：管理员维护可用班组。
- 账号管理：管理员创建账号、设置角色并为班组账号绑定班组。

## 7. 技术约束

- 前后端分离。
- 前端使用 Vue 3、TypeScript 和 Vite。
- 后端使用 FastAPI。
- 数据库使用 MySQL，字符集为 `utf8mb4`。
- 所有关键状态校验在后端事务中执行；前端按钮状态仅用于交互提示。
- 后端负责认证与角色/班组权限校验，不能只依赖前端隐藏菜单。

## 8. 尚待外部联调或现场规则确认

- 公司主系统查询流水号、出库和入库接口文档及脱敏样例。
- 投料是否联动真实库存及原料批号。
- 数量与重量在不同物料类型下的必填和守恒规则。
- 报废、返工、退回和撤销的审批规则。
- 工艺单的最终纸张尺寸、字段和排版。
- 是否未来允许一个账号属于多个班组；第一版已按一个班组账号只绑定一个班组实现。

## 9. 已确认并实现的分批流转升级（2026-09-04）

- 班组按扎板、退火、研磨、线切割、雕刻、电镀、检验、发货、转废顺序添加；管理员可新增、排序或停用，侧栏动态显示。
- “转废”是异常接收与汇总台账，不加入正常产品工艺路线，也不提供正常报工录入入口。
- 每次报工记录本批总量、转废、丢料、合格量、原因与工时；数量最多三位小数。合格 = 本批总量 - 转废 - 丢料。
- 分次接收不得超过所选批次剩余合格量。原始合格量为零的全损耗批只允许一次零数量确认，不制造合格产量。
- 独立转废/丢料异常从所选待加工料或待转批次余量扣减，要求具体原因；其他原因只记录说明，不扣数量。
- 整体流转单可展开每一道工序、每批报工、每次接收和异常原因，并查看操作者、班组和时间。
- 班组产量按工单展示合格、转废、丢料、已收、已转、待加工和待转；日期筛选为工单创建日期，不是日期内新增产量。
- 整单实物数量满足：计划投产 = 末序完成 + 在制 + 转废 + 丢料。班组合格产量按工序累计，不等同于整单完工量；全班组汇总不重复计算转废目的班组的同一损耗。

## 10. 已确认的导航、班组录入与流转总表整理

- 默认入口为“工单流转”；删除与其重复的“首页”菜单。
- 侧栏分为生产作业、班组作业、基础设置；基础设置仅管理员显示。
- 侧边栏不设置通用“扫码作业”入口。报工、接收和异常从具体生产班组的工单行进入，并在录入页内切换作业类型。
- 班组保留动态子菜单，工厂班组与演示班组分组折叠；班组账号优先显示“我的班组”。折叠不删除、不停用任何班组或记录。
- 班组账号的录入范围锁定为账号绑定班组；管理员从具体班组进入，可为该班工序代录。转废班组只显示报废台账，不作为正常报工入口。
- 总表默认收起工序明细，工单号与操作入口固定；转料批次条形码显示在批次记录和转料单中，不再把工单号显示为条形码。
- 总表扫码框接收转料批次号和回车后，保持在当前页面并弹出本次转料摘要；摘要提供流水号、来源、去向、数量、重量、接收进度和完整记录入口。
- 总表显示所在工序、计划/在制/完成、状态与转废/丢料摘要；全批次、接收记录和具体原因仍进入原详情页查看。
- 管理员在总表右上“新建工单”进入现有下单表单，原产品工艺快照和后端校验规则不变。

## 11. 已确认的前端视觉与交互改版（2026-09-05）

- 使用 Element Plus 的目标是获得成熟、统一的控件与交互基础，并在其上建立项目自己的工业后台设计语言，而不是直接套用默认皮肤。
- 改版需要同时提升视觉层级、信息组织、操作反馈、扫码体验、状态动画、图表表现、响应式和错误处理。
- 动画应短促、稳定、克制，帮助用户理解页面与数据变化，不能影响连续扫码和生产录入。
- 前端最终以可直接向甲方演示和交付的成熟商业后台为验收目标。
- 页面、组件、交互、响应式、测试和验收细则见 [前端视觉与交互改版需求](../frontend-redesign.md)。

## 12. 已确认的物料系统大小循环与编号口径（2026-09-05）

- 大循环与公司主系统对接，负责公司级订单或工件信息以及出库、入库结果。
- 小循环由本系统负责，记录热沉车间各工序之间的加工、转料、接料、异常和物料位置。
- 流水号用于定位公司主系统中的订单或工件信息；转料批次号表示某一次具体转料；Code 128 条形码编码转料批次号。
- 一个流水号对应一组工件或一张生产任务信息，第一版一张工单对应一个流水号，不采用每个物理零件一个流水号。
- 库房作为工艺路线固定的首尾边界，参与“库房 → 首序”和“末序 → 库房”的批次交接，但不人工报工。
- 转料批次号由本系统按 `TLYYYYMMDDNNNNNN` 自动生成；一个批次只关联一个流水号、一个上序和一个下序，但可以包含多个物料类型明细。
- 报工和实际转料分开保存，前端可以通过“报工并转料”连续完成；转料提交后物料先进入在途，下序允许少收和分次接收但不得超收。
- 下序首次接收后批次立即锁定；差额结束必须通过丢料、退回或其他原因处理，不能直接覆盖原转料数据。
- 同一流水号可以有多个转料批次；下序扫描批次条形码后直接确认该批数量和重量。
- 当前版本已实现持久化转料批次、批次 Code 128、未锁定批次编辑/作废、数量/重量分次接收、首次接收锁定、批次列表/详情/扫码接料、流水号追踪和 A4 双联转料单打印；旧工单号扫码接口仅保留为报工录入兼容入口。
- 公司主系统真实查询、出库、入库和对账仍待取得接口资料后联调；当前页面明确标为未对接，不展示伪造的大循环库存。
- 完整边界、字段、状态、查询、打印、数据模型和迁移要求见 [物料系统大小循环与编号需求](../material-system-requirements.md)。
