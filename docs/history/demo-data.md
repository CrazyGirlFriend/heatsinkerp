# 一期演示数据与体验路径

一期演示数据写入真实数据库，不是前端占位内容；重启服务或普通 `docker compose down` 后仍会保留。不要执行 `docker compose down -v`，否则会删除数据库卷。

## 一期示例

演示流水号：`DEMO-DIRECT-FLOW-001`

该流水号有两次独立交接，每批均为 24 件、4.800 kg：

1. 第一个班组转给第二个班组，状态为“已接收”。
2. 第二个班组再转给第三个班组，状态为“待接收”。

这组数据用来直观看到：同一流水号可以连续产生多张转料单；每张单只含本次转出和接收班组；接收后原单锁定；下一段由当前持有班组重新建立。

当前演示服务器中的两张批次为：

- `TL20260906000002`：下料班（演示）转给机加工班（演示），已接收。
- `TL20260906000003`：机加工班（演示）转给表面处理班（演示），待接收。

条形码均为 Code 128，编码内容与批次号完全一致。

## 推荐体验顺序

1. 用管理员登录，在“班组管理”和“班组长管理”查看班组及账号绑定；管理员在转料页面只能查看。
2. 进入“转料记录”，查看两张演示批次及批次条形码。
3. 在页面扫码框输入 `TL20260906000003` 并回车，确认会直接打开详情。
4. 进入“流水追踪”，查询 `DEMO-DIRECT-FLOW-001`，查看两段按时间排列的轨迹和最近一笔在途状态。
5. 用 `demo_cnc` 登录，可修改或作废待接收单；演示时建议只查看，以保留示例。
6. 用 `demo_surface` 登录，可看到“确认接收”；演示时建议不确认，以便继续展示待办。

旧演示班组长账号的初始密码由部署管理员单独提供；若用户已经修改密码，重新导入不会重置。服务器管理员密码沿用部署时单独交付的密码，不写入仓库文档。站点访问口令与账号密码是两层不同保护。

## 导入命令

系统已有至少三个不同班组的有效班组长后，执行：

```bash
docker compose -f docker-compose.yml -f docker-compose.demo.yml exec backend python -m app.seed_material_transfer_showcase
```

服务器执行：

```bash
sudo /opt/heatsinkrep/bin/docker-compose \
  --env-file /opt/heatsinkrep/.env \
  -p heatsinkrep \
  -f /opt/heatsinkrep/current/docker-compose.server.yml \
  exec -T backend python -m app.seed_material_transfer_showcase
```

脚本具备以下边界：

- 只复用有效 `TEAM` 班组长及其绑定班组。
- 不创建账号、不生成或修改密码。
- 不创建产品、工单、工艺、工序或报工。
- 条件不足时明确报告跳过，不猜测账号归属。
- 使用固定幂等键，重复执行不会重复建单或重复确认。

旧产品、工单、工艺和报工演示数据仍保存在历史表中，用于兼容性测试；一期导航不显示这些入口，新转料也不读取这些数据。
