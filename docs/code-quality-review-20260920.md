原始检查日期：2026-09-20。审计时代码基线 `39e08ad`，当时线上应用 `eb7b903` / `20260920T012302Z`。以下原始问题及行号保留作整改对照，后续状态见文末。

## 发现的问题

### P1：旧清库脚本的范围和当前物料模块不匹配

`backend/app/reset_business_data.py:15` 的固定列表会删除旧产品、工单、工序等 17 张表，却未包含后续新增的期初提交和流水号加急记录。`backend/app/opening_stock.py` 根据期初提交记录判断是否已提交；只删物料后保留该记录，不能视为完整重置。

建议废弃其作为“仅清物料”的入口，明确拆分清理范围，并对保留表做内容校验。本次清理未调用旧脚本，使用单事务、限定 7 张物料表的操作脚本，保留其他表、外键约束和编号计数器。

### P2：应用日志缺少统一请求标识、错误上下文和耗时

`backend/app/main.py:1` 未配置应用级日志及请求关联中间件；应用源码未发现 logger 调用。现有 Nginx/Uvicorn 能记录 HTTP 访问和未捕获异常，但不能可靠串起“某个用户的一次业务请求 → 服务处理 → 数据库失败”。例如 `backend/app/auth_api.py:19` 将数据库异常转换成 503，保留异常因果关系但没有显式记录诊断日志。

建议补充请求 ID、路由模板、状态、耗时、经过筛选的错误类型及必要异常堆栈。不能直接记录请求体、Authorization、Cookie、口令、主系统令牌或数据库凭据；业务拒绝和程序错误应区分级别。

### P2：前端异常缺少可追踪记录

`frontend/src/main.ts:13` 没有集中异常处理；`frontend/src/services/inventoryStream.ts:86` 将网络中断、无效 JSON、快照校验失败等统一转成重连状态，原始原因没有保留下来。`frontend/src/services/httpClient.ts:95` 保留 HTTP 状态和响应体，但没有请求关联标识或统一诊断记录。

页面保留旧数据并提示重试的处理是有价值的；问题在于后续难以定位原因。建议集中捕获意外异常，记录脱敏摘要及请求 ID，对重连错误限频；无需在每个正常请求或组件中堆 `console.log`。

### P2：业务审计有覆盖，但账号和班组管理不完整

`backend/app/material_transfer_workflow.py:61` 记录物料变更的动作、操作者、时间、前后差异；创建、修改、作废、接收等路径会调用。`backend/app/team_business.py:81` 和 `backend/app/serial_urgency.py:62` 也分别记录用途/期初授权、加急事件。

但 `backend/app/admin_api.py:223` 的账号修改直接提交，当前管理员参数以 `_` 接收，没有相应审计事件；创建、删除账号以及班组维护也缺少统一历史。账号绑定班组、停用、密码重置后，无法仅凭审计记录完整回答“谁在何时改了什么”。应记录动作和脱敏前后值，密码只记录“已重置”，不记录密码或哈希。

### P2：格式和可读性不统一，也没有自动约束

例如 `frontend/src/pages/FactoryLivePage.vue:175` 把循环、条件、事件和多层模板挤在一行，脚本也多次使用分号合并状态修改。其他页面同样存在超长行；本次扫描最长前端行超过 1,300 字符。后端部分新模块混用紧凑写法和较规范的多行写法。

这包括此前实现的玻璃大屏，属于需要改进的问题。建议先建立格式化与静态检查基线，再按模块整理；不要一次无差别格式化整个仓库，让逻辑变更和格式变更难以分辨。

### P3：注释和类型边界覆盖不均

库存锁顺序、提交后推送、回滚、数据来源保护等关键位置已有解释性注释，例如 `backend/app/material_stock.py:201`、`backend/app/inventory_events.py:1`、`backend/app/factory_stream.py:27`。不是“完全没有注释”。

但大屏中请求版本与推送版本如何防止旧数据覆盖、断线冻结与恢复等逻辑缺少就近说明。后端本次 AST 统计 266 个函数中 100 个有返回类型注解；部分汇总接口直接返回字典，例如 `backend/app/factory_overview.py:175`，与前端类型分别维护。建议优先补重要业务边界的说明、服务函数类型和响应模型，不要求每行都写注释。

## 建议顺序

1. 保证维护清理范围准确、可备份、可回滚、保留数据可核对。
2. 补后端请求关联与异常日志、前端集中错误处理，补账号和班组管理审计。
3. 建立格式化、静态检查和 CI，再逐模块整理格式与关键注释。

事务、幂等键、库存行锁、角色权限、类型检查与测试是已有基础；这些优点不抵消上述维护性、审计和诊断缺口。
