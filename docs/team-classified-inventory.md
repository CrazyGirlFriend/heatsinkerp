# 八班组分类库存明细

## 列表与操作

八个班组共用一个库存明细组件，默认列为：流水号、材质、规格、物料类型、来源（普通班组为“上序班组”）、当前件数、当前重量、操作。相同流水号、材质的相邻单元格合并。

- 按 **流水号 + 材质 + 规格 + 物料类型 + 来源** 分组。同组多次接收合计余额；不同类型、规格、上序班组分别显示。批次号仍在二级详情，不增加 CK 单号。
- 库房保留外部来料、外部退回、车间转入及具体来源单位/班组；其他班组直接显示上序班组，库房也可以是上序。
- 默认显示有实物结存的分组，包括只有重量的物料。废料分类规则不变，不因列表统一而允许废料转入普通班组。
- 行内“明细”展示该分组的来源批次及余量，含已出完历史；行内“出库”仅提供该分组有余额的批次。丢失登记在实际来源批次上办理。顶部“新建出库”继续允许跨分组选料、向同一下序多批出库。
- 点击流水号查看完整流水号历史，不把它与单个分组明细混为一谈。
- 保留类型、来源、材质、日期、加急、分析条件、自选列及字段搜索。数值按分组余额查询，搜索字段临时置于首列。图表筛选仍先选符合条件的流水号，再展示其符合分类/来源条件的当前库存。
- 普通班组列设置使用独立账号/班组键；库房沿用现有列设置。待接收量不拆摊到库存行，避免同流水号多个分类重复显示待接收总数。
- 默认每页 10 条，可选 20/50/100 条，整页上下滚动。复用现有白紫样式，不新增库存页或图表。

## 数据和权限

库存由原收发、丢失记录计算：提交转出立即扣减；内部下序接收后计入下序库存；确认不重复扣减；作废未确认批次恢复上序库存。日期用于筛选发生过流转的分组，不生成历史库存快照。实时推送保留搜索草稿、页码和已打开详情。

管理员业务只读；班组账号只能操作绑定班组。新增的共享只读接口不授予出入库权限，库房手工入库、废料去向限制和逐批确认规则保持不变。

## 接口

- `GET /api/team-materials/{team_id}/inventory`：全部班组的分类库存；参数包括 `query`、`search_field`、`search_operator`、`source_team_id`、`material_type`、`availability=current|available|scrap|all`、日期和分页。库房另使用 `receipt_source=external|return|internal`。
- `GET /api/team-materials/{team_id}/inventory/{group_id}/sources`：所选分类/来源内的已接收批次；`current_only=true` 仅保留有余额的来源。
- `group_id` 是该分组最早接收记录的 ID，不是对外批次号。查询校验该记录属于目标班组，不能拿另一班组的 ID 读取本组来源。
- 旧 `warehouse-inventory` 两个只读路径继续兼容且仍仅限库房；新前端统一使用 `inventory`。

新旧库存组件合并为 `TeamInventory.vue` / `TeamInventoryDetail.vue`，移除不再使用的 `TeamSerialOverview.vue`；后端仍复用原分组和余额查询，无需数据迁移。
