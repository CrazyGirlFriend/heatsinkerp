# 代码检查、诊断和维护

## 本地检查

在仓库根目录使用独立 Python 环境，避免系统环境的 FastAPI 等版本与生产要求不同：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-dev.txt
.venv/bin/python scripts/check_backend_quality.py
```

在 `backend` 中执行 `../.venv/bin/python -m pytest -q`。在 `frontend` 中执行：

```sh
npm ci
npm run lint
npm run format:check
npm test -- --maxWorkers=1 --minWorkers=1
npm run build
```

CI 使用 Python 3.12 和 Node 24；`.github/workflows/quality.yml` 在推送和 PR 时运行上述检查，并验证空库迁移。CI 不执行部署、不连接生产数据库。

ESLint 检查全部前端源码及测试；TypeScript 严格检查保留。Ruff 对全部后端应用、测试检查语法和未定义名称，`scripts/quality-scope.json` 中的核心模块另外检查导入、常见错误和格式。Prettier 当前覆盖大屏、请求与推送、诊断等已整理模块；`npm run format` 只格式化该清单。新增或整理模块应加入清单，逐步扩大范围。不能把这一基线描述成“所有旧代码都已格式化”。

## 请求与错误诊断

- 应用为每次业务 HTTP 请求生成随机 `X-Request-ID`，不采用客户端传入值；跨域响应开放读取该头。
- 后端 JSON 日志含事件、请求编号、路由模板、方法、状态、耗时。错误记录异常类型及最多 12 个代码位置，不序列化异常消息、SQL 参数、请求正文、查询参数、Cookie、认证头或局部变量。
- 普通未处理错误统一返回通用 500 响应；已开始的流不能改写状态，记录错误后中断，由前端重连。日志中流的状态仍是已经发送的状态，故障以同编号的 `request.failed` 为准。
- 中间件逐块转发 SSE，不缓冲正文。断开时释放请求上下文。数据库健康检查转换成 503 前记录脱敏故障。
- 两个后端 Dockerfile 均关闭 Uvicorn 默认访问日志，使用上述应用日志。Nginx 常规访问日志只写方法、状态、耗时和上游请求编号；基础设施自身的错误日志不在此应用白名单的控制范围内。现有 Docker 日志轮转保持不变。
- 前端统一捕获 Vue、浏览器未处理异常及请求、推送故障。开发者工具控制台的 `[heatsink]` 条目只包含固定错误分类、HTTP 状态和经过验证的请求编号。每类 30 秒最多一条，内存最多保留 50 条；不持久化、不上传新的诊断接口。
- 正常鉴权拒绝和主动取消不产生网络故障诊断；推送区分连接失败、读取失败、超时、结束、超大消息、无效 JSON、无效快照和消费回调错误。

排查时先从浏览器网络响应或诊断条目取得请求编号，再查后端同编号日志。不要把请求正文、令牌或数据库异常参数附到诊断日志。

## 管理审计和迁移

`20260920_0016` 新增 `admin_audit_events`。账号、班组的创建、修改、删除与审计在同一事务中提交；审计失败会回滚业务修改。停用、绑定班组、密码重置均包含在账号修改中。密码只记录 `password_reset` 布尔标志，不记录口令或哈希。

审计保留操作者 ID/姓名、目标类型/ID、动作、请求编号、时间以及白名单字段前后值。操作者和目标使用历史快照，不设删除级联，因此删除账号、班组不会删除历史。没有新增公开查询接口，运维可通过受控数据库访问检索；本次不补造上线前的历史事件。

发布时需要升级前后端，并执行 `alembic upgrade head`（现有容器启动命令已执行）。迁移只增加审计表，不清空物料或改变库存。降级保留审计，不提供删表式自动降级。

## 物料维护清理

`python -m app.reset_business_data` 默认只预览。它现在仅处理当前物料七表：转料、出库批次、损耗、物料事件、期初提交、加急状态和加急事件。旧工单、产品、账号、班组、用途、管理审计及编号计数器均保留。

实际执行必须同时提供 `--apply`、与目标完全一致的 `--confirm-database`、`--backup-file`、匹配文件的 `--backup-sha256` 和 `--maintenance-confirmed`。必须先停止业务写入并制作新备份；参数只确认操作者已完成维护准备，不能自动证明备份来自该库或足够新。

脚本在单事务内检查未知外键依赖，保留外键约束，先删流转来源链的叶子，再删父记录；提交前校验七表归零并比对所有保留表的内容摘要。发现依赖、来源循环或保留数据变化即回滚。不会重置编号，也不会执行旧的全业务/工单清理。
