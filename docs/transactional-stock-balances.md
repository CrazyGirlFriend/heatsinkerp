# 事务库存余额

库存查询使用 `material_stock_balances`，每个已接收且受库存管理的批次一行，关联原批次和班组。流水号、材质、类型及来源仍取原单据，不改变条码或现有接口字段。

- 入库或期初库存增加本班组余额。
- 转出提交立即扣减来源余额，内部待接收计入在途；外部出库不计入内部在途。
- 接收增加目标班组余额，不再次扣减来源；外部确认只调整待确认/已确认分类。
- 未接收修改按差额调整，作废退回余额，丢失单扣减来源。
- 所有变动与原单据在同一数据库事务内。唯一幂等键、来源行锁和非负约束继续生效。

`stock_balances.py` 的 ORM flush 钩子以变更前后差额更新余额，覆盖普通业务、期初及演示数据入口；保存点回滚和事务回滚同时撤销余额。ORM 批量增改删绕过这些钩子，因此明确拒绝。直接 SQL 不受钩子保护，只能用于已停写、已备份的维护流程，并在恢复服务前重建对账。

## 迁移

停写并完成可恢复备份后执行 Alembic `20260923_0017`。迁移只新增余额表，按已有单据和丢失记录回填，核对全部批次的件数、重量及分类计数；负库存或已有余额不一致时中止，不覆盖旧账。可在中断后重跑；不要与旧版应用同时写入。回退需恢复匹配版本的应用与数据库备份。

历史曲线仍查原始流水；余额表回答当前库存，不替代历史。
