# 班组库存口径

## 外部收发操作与权限（2026-09-28）

| 操作 | 使用账号 | 操作步骤 | 库存变化 |
| --- | --- | --- | --- |
| 库房接收外部来料 | 绑定库房的班组长账号 | 手工入库 → 核对来源、流水号、类型、件数和重量 → 确认入库 | 立即增加库房库存，单据锁定，无需再次签收 |
| 库房对外出库 | 绑定库房的班组长账号 | 选择本班组物料 → 对外出库 → 填写去向和数量 → 开单 → 实际发出后确认出库 | 开单后减少可转出量，状态为「待出库」；确认后减少库房库存 |
| 检验对外发货 | 绑定检验的班组长账号 | 选择本班组物料 → 发货 → 填写去向和数量 → 开单 → 实际发出后确认发货 | 开单后减少可转出量，状态为「待发货」；确认后减少检验库存 |

开单和确认可以由同一本班组账号完成，不是新增审批环节，也不要求外部收货人登录本系统。检验转给库房属于内部转料，由库房签收，不能用检验「确认发货」替代。

这里的班组长账号指角色为 `TEAM`、账号及所绑定班组均启用的账号。系统管理员可查看和配置账号，但不能代办上述收发；其他班组也不能代办。服务端同时校验角色、绑定班组和操作类型，不只隐藏前端按钮。账户或班组停用后，旧登录令牌也不能继续提交。

本次仅统一操作提示、详情/打印/列表状态，并补充失效账号的前端确认保护；库存事务、API 状态值、幂等与锁定逻辑不变。「对外待确认」仍可作为汇总指标名称，单笔记录按业务显示「待出库」或「待发货」。全厂口径说明移除重复句子。

## 当前修正（2026-09-28）

**下序签收前，已发出的物料仍是上序班组库存；但不能再次出库。**

- 八个班组的「库存明细」默认显示「库存件数」「库存重量」，直接使用接口 `owned_quantity/weight`；列表默认显式查询 `availability=owned`。全部发出、尚未签收的记录仍可查看。
- 举例：本班有 100 件，发出 30 件未签收时，库存仍为 100 件，可转出 70 件，待签收 30 件；改为发出 20 件时库存仍为 100 件、可转出 80 件；签收后本班库存为 80 件，下序库存增加 20 件。作废恢复可转出量，不重复增加库存。
- 悬停库存数字可查看待签收和可转出量；「明细」中按来源批次显示库存、可转出/可处理量及待确认量。对外待确认与内部待签收分别显示，仍使用原确认流程。
- 材质结存、物料性质结存、流水号详情的库存字段同步使用 `owned`；件数和重量继续分列。移除“转出即扣减，待接收不计入结存”页脚说明，不修改侧边栏或页面布局。
- 自选列和顺序保留。此前选择的 `on_hand` 列不改变数值，明确改名为「在库件数/重量」，指尚未发出的余额；在「显示列 → 恢复默认 → 应用」可切换到新的库存列。旧 `availability=current` 等显式筛选继续保留原义。
- 出库选料仍用可转出/可处理余额，不能按包含待确认物料的库存总量出库。后台写入、锁、幂等和接口原字段含义均未调整，无数据库迁移。

## 业务口径

件数与 kg 独立统计；以下都是截至查询时点的账面余额，不是盘点或实称结果。

| 名称 | 含义 | 接口字段 |
| --- | --- | --- |
| 归属余量 | 本班在库，加上本班已发出但尚未完成确认的物料 | `owned_quantity/weight` |
| 在库余量 | 本班尚未发出的账面余量，含废料 | `on_hand_quantity/weight` |
| 可转出量 | 正常料尚可发出的余额 | `available_quantity/weight` |
| 可处理量 | 废料尚可处理的余额，仍受原去向限制 | `scrap_available_quantity/weight` |
| 转出待签收 | 内部转料已发出，下序尚未签收 | `in_transit_quantity/weight` |
| 对外待确认 | 库房对外出库或检验发货尚未确认 | `external_pending_quantity/weight` |

`owned = on_hand + reserved`；`external_pending = reserved - in_transit`。`reserved` 仍是全部转出待确认，不改变旧字段的含义。待接收来料不计入接收班组的归属。

例如入账 100 kg，发出 30 kg 后，归属仍为 100 kg，在库及可转出为 70 kg，待签收为 30 kg；改为 20 kg 后在库恢复到 80 kg；下序签收后，上序归属为 80 kg、下序归属为 20 kg。作废只恢复在库，不额外增加归属。

## 接口及当前实施边界

| 页面/用途 | 查询位置 | 本阶段处理 |
| --- | --- | --- |
| 班组分类库存 | `/api/team-materials/{id}/inventory` | 新增 `availability=owned`；旧默认 `current` 及其他筛选含义不变 |
| 分类来源批次 | `/inventory/{group_id}/sources` | 同步派生余额 |
| 待签收下钻 | `/inventory/{group_id}/pending-outbound` | 按本分类的来源批次关联查询，不把同流水号其他来源混入；分页返回批次、下序、件数、重量、转出时间与内外部类型 |
| 出库选料 | `/api/team-materials/{id}/stock` | 原 `available/dispatchable` 条件不变，不因归属非零而放行 |
| 班组及材质汇总 | `/api/team-materials/{id}/overview` | 统一余额查询增加派生字段 |
| 流水号汇总 | `/api/team-materials/{id}/serials` | 统一余额聚合增加派生字段；不是新增物料平衡接口 |
| 全厂/大屏 | `/api/factory-overview`、`/live` | `totals`、班组 `balance` 增加字段；实时消息契约同步。页面仍沿用原显示，待样板确认后统一 |
| 全厂管理矩阵 | `factory_dashboard.py` | 已按 `on_hand + reserved` 统计；推广时复用统一字段 |

分类库存、来源、待签收列表和班组余额返回 `as_of`；全厂继续使用已有 `as_of`。日期过滤仍表示“期间发生过业务的当前库存”，不把当前余量作为历史日期余额。

本轮不创建数据库表或迁移，不调整写入事务、行锁、幂等、库存约束或权限。新的归属字段由原事务余额查询派生，不增加缓存或第二份库存账。

### 研磨样板使用说明

1. 打开「班组工作台 → 研磨 → 库存明细」。列表显示流水号、材质/规格、类型/业务、上序班组、在库余量及操作。2026-09-27 修订将累计收发移入行内“明细”，已随 `d43c015` 发布 `20260927T090835Z`。
2. 「在库余量」显示在库件数/重量，在同一栏内补充「归属余量」和「可转出量」，不再默认拆成三列。2026-09-27 修订不再展示“尚未转出 / 部分转出 / 无结存”等状态文字；待签收数量在行内“明细”查看。已有用户自选列及顺序不覆盖，仍可在「显示列」中恢复默认；独立余额列保留为可选项。
3. 点击行内“明细”，来源结存表按批次展示在库、归属和丢失的件数/重量；收发记录表按每笔实际批次展示收发及确认状态。点击“查看待签收批次”，可查看对应批次、下序、件数/重量和转出时间；点击收发表的批次号可打开该笔原单。主列表移除“最早在库接收”，具体接收时间保留在来源结存表。
4. 归属非零但可转出为零的记录仍显示，出库按钮不可用。废料显示「可处理量」，仍按原有去向限制操作。
5. 页尾显示本次账面查询时点。业务推送更新余额和待签收明细，不清空正在输入的筛选或出库草稿。
