# 物料平衡与库存归属统一实施计划

日期：2026-09-27。

状态：阶段一接口基础及回归、阶段二研磨样板开发及本地验收已完成；等待样板确认后推进其余阶段。未推送、未部署。详细口径、使用说明与验收记录见 [库存归属说明](inventory-ownership.md)。

## 1. 目标与边界

在已有物料流转、库存余额及批次追踪基础上，让用户明确看懂：料归谁、多少仍在库、多少已发出待签收、还能转出多少、正常料与余料和废料分别去了哪里。

- 下序确认签收前，发出物料仍归上序班组；签收后归下序。
- 提交出库仍立即扣减在库及可再次出库的余量，不把待签收物料重新变成可出库库存。
- 废屑、废泥按流水号分别称重回库。不同类型各有独立批次和条码，可以合并打印，不新增整单号。
- 首轮只统一口径、展示及账面去向汇总；不重建库存账、不重复录入、不增加工艺或报工流程。
- 不新增一级菜单或独立物料平衡页面，复用库存明细、流水号详情与管理员全链路追踪入口。
- 不修改登录、品牌、侧边栏架构、监控或部署架构；服务监控由其他任务负责。保留其他任务的未提交修改。

## 2. 已有能力：直接复用

| 已有能力 | 当前实现依据 | 本轮处理 |
| --- | --- | --- |
| 来源批次关联、拆分转出、独立批次 | `MaterialTransfer.source_transfer_id`、现有出库流程 | 沿用，不新增人工来源字段 |
| 期初、入库、出库、接收、作废、丢失 | 现有业务单据与审计事件 | 沿用，不重复登记 |
| 废品、废料、废屑、废泥与余料分类 | 库房分类及八班组分类库存 | 沿用类型与去向限制 |
| 事务库存余额及防超扣 | `material_stock_balances`、`stock_balances.py` | 保留原扣减、行锁、幂等及约束 |
| 本班组收发历史、全链路追踪 | `team_serial_history.py`、`material_trace.py` | 增补汇总表达，不重做画布 |
| 全厂归属统计 | `factory_dashboard.py` 的 `on_hand + reserved` | 作为统一归属定义的现有依据 |
| 实时更新 | 现有事务通知、消息队列与 SSE | 复用，不能改成仅手工刷新 |

成品率不等于物料平衡，不把全部转出都称作成品或合格产出。历史未关联来源、未纳入库存或缺少类型的记录继续明确提示，不能补造来源或分类。

## 3. 固定统计口径

下列公式分别用于件数与重量；重量沿用 Decimal、kg 和三位小数。它们是收发台账关系，不证明加工前后件数或实物质量已经独立核实。

| 页面名称 | 定义与现有字段映射 |
| --- | --- |
| 归属余量 | `on_hand + reserved`，包括本班在库和已发出但未完成确认的物料 |
| 在库余量 | `on_hand`，账面尚未转出的余量，包含废料；不是独立盘点结果 |
| 转出待签收 | 内部转料待签收，即 `in_transit`，归上序，属于 `reserved` 的一部分 |
| 对外待确认 | 库房对外出库、检验发货未确认部分，即 `reserved - in_transit`，单列且不称内部在途 |
| 待接收 | 指定本班为下序、但本班尚未签收的来料；不计入本班归属或可出库量 |
| 已完成转出 | 内部下序已签收或对外出库已确认，即 `dispatched` |
| 正常可出库量 | 沿用正常物料 `available`，不含发出待确认及废料 |
| 废料可处理量 | 沿用 `scrap_available`，只能走既有废料允许的去向，不混入正常可用量 |

班组来源批次的账面关系：

> 已接收（含期初入账）＝归属余量＋已完成转出＋已登记丢失。
>
> 归属余量＝在库余量＋转出待签收＋对外待确认。

- 全厂归属总量等于各班组归属余量之和，不额外再加一次在途。历史班组仍有余额时不能静默遗漏。
- 下序签收只转移归属并增加下序在库，不能再次扣减上序在库；未确认作废恢复在库，不额外增加归属总量。
- 筛选、排序、分页合计、自选列及导出/打印中出现的库存字段必须采用其明确名称对应的口径，不能只改表头。
- 类型转换保留来源类型和本次转出类型：待签收废屑不能成为正常可出库量；去向分类按转料单类型，来源追踪保留原批次，两种视角不可相加。
- 日期筛选“期间有收发的当前库存”和“某段期间的期初/期末余额”须明确区分。第一轮平衡汇总截至当前查询时点；历史期间继续使用现有真实事件重建能力，不用当前余额冒充历史实存。
- 收发回流可能重复经过同一班组，属于真实周转，不是全厂新增投入；不得用各班组累计收到的总和作为全厂投入。

## 4. 分阶段实施

每阶段先完成对应验收，再独立提交代码并记录结果。计划状态、开发完成、测试通过、已部署分别记录，不能混用。

### 阶段一：统一接口口径与回归基线

- [x] 列出库存明细、材质归类、全厂概览、材质班组表、追踪及大屏的接口与字段对照，识别在库/归属混用位置。
- [x] 复用现有余额，统一输出归属、在库、内部待签收和对外待确认；已有字段不静默改义，必要时增加兼容字段，不落第二套余额表。
- [x] 将正常料、废料及转出类型的分类边界纳入后端汇总测试。
- [x] 覆盖提交、修改、签收、作废、丢失、内部回流、外部出库及独立批次的状态变化。

验收：同一时点、同一筛选范围内，逐批合计、班组汇总与全厂归属对得上；归属增加不能扩大出库上限。预计无需数据库迁移，若发现确需改变存储模型，先单独说明，不自动扩张范围。

### 阶段二：研磨班组样板

- [x] 先修改研磨库存明细，展示归属余量、可转出量及转出待签收，件数和重量同时保留。
- [x] 正常行显示可出库量，废料行显示可处理量；不因本班归属尚有物料就允许再次发出。
- [x] 在库已为零、但仍有转出待签收的分组仍能在默认归属视图中看见；选料继续只读取实际可转出余量。
- [x] 待签收数字可下钻批次、下序和时间；研磨出库记录的内部状态明确为「转出待签收/已签收」，接收侧仍为「待接收」。
- [x] 保留现有自选列、搜索、日期、分页及权限；不增加顶部大统计卡片，不缩小字号挤入更多字段。

样板修订：按用户反馈保留原八列及累计收发、丢失、在库批次数和接收时间；归属/可转出补充到原在库栏，待签收下钻放在累计收发栏。独立余额列仍可自选，不再作为默认三列替换原明细。

验收：用“100 kg 发出 30 kg”的状态序列核对列表、详情与实际选料；在独立 Chrome 检查阅读与对齐。样板先给用户确认信息安排，再铺开其他页面。

### 阶段三：推广八班组与全厂展示

- [ ] 通过共用组件推广到其他七班组，不复制八套页面。
- [ ] 库房来源、废料分类、对外出库和检验发货的特例保留，外部待确认独立展示。
- [ ] 同步材质归类、全厂概览、材质班组表和大屏；班组物料总量采用归属口径，明确标为在库的指标继续采用在库口径。
- [ ] 同步统计说明、空态、筛选名称及已有库存数值的展示位置，避免同名不同义。
- [ ] 验证既有实时推送同时更新上下游、汇总与大屏，并保留筛选、草稿及选料保护。

验收：同一测试流水号在八班组及全厂相关页面口径一致；全厂归属总量不因内部转料或废料回库增减。对外确认后才从归属总量中移出。

### 阶段四：在已有详情中补物料去向汇总

- [ ] 班组流水号详情按具体材质汇总期初、接收、归属余量、完成转出和丢失；完成转出按正常料、余料、废品、废料、废屑、废泥展开。
- [ ] 管理员全链路中补充外部投入、归属分布、已确认对外流出和丢失等账面去向，不将内部周转反复算投入。
- [ ] 复用现有批次详情，每项汇总可找到支撑它的完整记录，不受列表当前页限制。
- [ ] 显示“账面统计”及必要的历史缺项提示，不宣称“实物已平衡”。未知字段不是零，外部退回等不完整来源关系不凭备注补连。

验收：逐笔来源、分类去向及汇总可勾稽；无来源历史、跨班组回流、同流水号不同材质、仅重量的废屑废泥均不误算。

### 阶段五：联合验收与交付

- [ ] 完成后端状态与汇总测试、前端组件测试、类型检查和生产构建，并记录实际结果。
- [ ] 使用隔离测试数据走完整操作，不在生产库写入演示料或清理真实业务。
- [ ] 独立 Chrome 检查样板与关键联动页面；不使用 Codex 内置浏览器，复用并关闭本任务创建的浏览器会话。
- [ ] 记录接口查询次数、响应耗时与实时更新结果，与改造前同环境基线比较，防止增加逐行请求或重复历史聚合。
- [ ] 同步一期口径、用户说明及页面职责文档，明确归属与在库的关系。
- [ ] 整理逐阶段提交与验收记录；收到发布指令后再推送部署，执行线上只读核对及回退准备。

## 5. 必须通过的业务样例

下表仅为隔离验收数据，单位 kg，不是线上库存。

| 场景 | 上游归属 | 上游在库 | 上游转出待签收 | 下游归属 | 全厂归属 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 上游已入账 100 | 100 | 100 | 0 | 0 | 100 |
| 发出 30，尚未签收 | 100 | 70 | 30 | 0 | 100 |
| 待签收由 30 改为 20 | 100 | 80 | 20 | 0 | 100 |
| 下游签收 20 | 80 | 80 | 0 | 20 | 100 |

其他独立场景：

- 100 kg 发出 30 kg 后作废：恢复上游在库至 100，归属仍为 100；重复作废/确认不重复变更。
- 同一流水号的正常料与废屑、废泥分批回库、分别签收，只转移归属和类型，不增加全厂投入；可合并打印，不共用批次号。
- 件数为零、重量大于零的废屑，仍参与相应重量汇总、分页筛选及去向追踪。
- 100 kg 提交对外出库 30 kg：在库 70、对外待确认 30、归属 100；确认后归属 70，不能算内部在途。
- 丢失按有效来源扣减一次；不把已经退库或仍持有的废料再次列为丢失。
- 两名操作人并发出库、重复请求、确认与修改冲突，保持现有防超扣、幂等和版本检查。
- 尚有归属但可出库为零、停用班组仍有余额、未追踪历史、跨日签收、实时断线重连等边界均有明确结果。

## 6. 后续阶段：不包含在首轮实现中

- 加工损耗与实际丢失的结构化区分，以及是否需要审批、由谁审批。
- 实称剩余、核对快照、差额原因及处理记录；不预填账面重量，不自动凑平。
- 废泥湿重、干重、金属净重及电镀增重等计量口径；未确定时不能宣称物理质量守恒。
- 工艺生产、数量转换、报工或加工结算，不因本计划自动引入。

用户已确认废屑废泥可按流水号称重回库，但尚未确认上述实物核对及损耗审批流程。第一轮可先完成清楚、可追溯的账面表达，不以补齐这些后续流程为前提。
