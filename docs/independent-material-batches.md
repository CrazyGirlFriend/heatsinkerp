# 独立批次与合并打印（2026-09-18）

状态：已提交并推送 `6fdf069`，已配套发布 `20260918T045500Z`；数据库与原始批次保留，发布验收见 [服务器部署记录](server-deployment.md)。

本规则取代早期“CK 整单 + TL 明细”的业务设计。流水号表示工件资料，批次号表示一次实际物料交接。

## 操作规则

- 一行物料一个批次号、一个 Code 128 条形码。不同流水号、不同物料类型各有自己的批次号；同来源拆出半成品和废屑也分批。
- 一次可选多条物料向同一下序出库，后台一次事务校验全部来源余量，失败全部回滚。重复提交沿用幂等键，不重复生成批次或扣减库存。
- 多批可以打印在同一张纸上，每行保留自己的条码、流水号、类型、件数、重量、上下序和资料。不生成新的整单号、整单条码。
- 下序扫码打开对应批次，只确认这一批。同次提交的其他批次仍可独立修改、作废、接收；已确认批次锁定。
- 提交出库立即扣减上序库存，内部交接计入在途；下序确认后计入下序库存。库房对外出库、检验发货由本班组逐批确认，不再扣第二次。
- 出库记录按批次分页，可组合物料类型、方式、下序、状态、日期和关键词筛选。勾选当前页多个批次后点“合并打印”；打印前重新读取各批最新内容，读取失败不打印旧数据。数量多或内容长时完整续页，不截断资料。

## 查废屑

1. 库房 → 入库记录 → 类型“废屑”，可叠加来源、日期、流水号查每次入库。
2. 库房 → 出库记录 → 类型“废屑”，可叠加日期、状态、外部去向关键词查每次出库。
3. 库存明细选“废屑”看当前余量；已出完的记录仍可在出入库记录查到。只有重量、件数为零的批次不遗漏。

## 接口与兼容

- `POST /api/team-materials/{team_id}/outbound-batches`：请求沿用 `idempotency_key`、`lines`、去向及说明；响应为 `{ "items": [完整独立批次记录] }`，无整单号。每行包含 `batch_no`、`barcode_payload`、`serial_no`、`material_type`、`quantity`、`weight`、状态与版本等。
- `GET` 同路径：每行一个独立批次。支持 `material_type`、`entry_kind`、`next_team_id`、`status`、`query`、`date_from`、`date_to`、`urgent_only`、`page`、`page_size`。默认十条。`query` 为字面包含匹配，覆盖批次、流水号、材质、外部去向。
- 详情/修改/作废沿用 `/api/material-transfers/{batch_no}`；接收用 `/confirm`，库房出库/检验发货确认用 `/confirm-outbound`，核对退回用 `/reject`。确认带独立批次的 `expected_version` 与 `idempotency_key`。
- 旧 `POST .../dispatches` 同样只生成独立批次，不再生成 CK。旧 GET/确认接口仅为历史集成保留；当前页面不提供整组确认。
- 原 `TL…` 批次号不改号；原 `CK…` 仅保留历史查找关系。扫描旧 CK 后显示各个真实批次，分别操作，重新打印也是每批一个条码。退料可关联已确认的出库批次号，旧 CK 关联校验继续兼容。
- 首页、待接收徽标、大屏批次数按真实批次计数，不再将一次提交的多批算成一批。件数和重量仍按实际记录计算。
