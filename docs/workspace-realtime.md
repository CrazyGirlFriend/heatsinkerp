## 2026-09-23 通知范围修复（已发布）

`inventory-changed` 保留 `changed: true`，新增以下可选字段。首次连接和旧服务的通知不带范围，客户端仍全量同步；后续业务通知仅让相关班组重读当前筛选。全厂视图仍响应所有库存变化。

| 字段 | 语义 |
| --- | --- |
| `team_ids` | 班组 ID 数组；`null` 为全部班组，空数组表示没有库存变化，缺省表示首次连接或兼容旧通知 |
| `directory_changed` | 班组目录或班组业务选项发生变化，重新读取目录 |
| `accounts_changed` | 账号管理列表需更新，不使无关库存页重查 |
| `current_user_changed` | 当前连接的账号配置改变，需重新获取身份及操作权限 |

新登录不发库存通知，注销只触发对应会话复核；账号停用、重设密码仍使已有无效连接立即退出，心跳继续鉴权。通知不会向客户端泄露会话摘要或其他用户 ID。普通物料通知不额外请求 `/auth/me` 和完整班组目录。

合并通知保留所有班组范围及权限标记；跨日与局部事件同时到达时升级为全班组刷新，避免其他班组的日期筛选及机器人大屏“今日”数据停在昨天。班组汇总和库存列表增加有界的共享只读结果，每次请求仍鉴权、业务提交立即失效，详见 [性能与容量验收](performance-and-capacity.md)。前后端已配套发布 `20260923T080136Z`，旧页面需重新加载程序一次，后续业务仍实时推送。

## 更新方式

- 首页继续使用原 `GET /api/factory-overview/stream`。
- 机器人大屏使用 `GET /api/factory-overview/live/stream`，接收 `factory-live` 完整快照；保留专用的最近 100 批、今日收发和八班组数据，不拿首页的 12 批摘要代替。原每 30 秒请求数据的计时器已移除，1 秒计时器仅用于时钟、等待时长及播报轮换。
- 班组工作台使用 `GET /api/factory-overview/changes`，接收轻量 `inventory-changed` 通知，再按当前班组、页签、页码及筛选条件读取原接口。不是固定间隔轮询，也不把全库明细推给每个浏览器。连续通知在 100ms 内合并，读取期间再有变化会补读最新状态。
- 工作台的流水号台账、待接收、库存、出库、入库、丢失、材质归类及班组分析跟随更新。独立的全厂分析页、全局转料查询页不在本轮扩展范围。

## 操作连续性

- 普通更新不修改地址、不回第一页、不重置未提交的搜索文字，不关闭出库、入库或详情窗口。后台读取时保留表格，失败明确提示并保留上次结果。
- 已打开的单据和选料表单不被推送强行覆盖，提交时仍校验最新权限、余量和单据版本；不能将填写中的数值当作库存预留。
- 账号停用、改绑或班组失效仍执行原权限处理，不能为了保留草稿继续提供无权操作的按钮。
- 大屏库存和班组指标直接接收更新。暂停轮播、悬停或键盘阅读时，暂存最新播报列表并显示“播报待恢复”；恢复后应用最新列表，机器人仍只跟随可见第一条，不回放积压的动画。

## 连接与部署

- 复用首页的 Bearer 请求头、访问锁 Cookie、断线退避重连和 45 秒停滞检测；凭证不放入 URL。
- 页面隐藏、离开或卸载时关闭所属连接，恢复可见时重新订阅并读取完整最新状态。后台不积累连接或通知队列。
- 15 秒心跳只校验权限、维持连接，不周期查询库存。按工厂时区跨日时额外更新一次大屏和台账，避免没有业务操作时“今日”统计停留在昨天。
- 数据库事务成功后才发布，回滚和幂等重放不制造重复事件。范围包括内部转出/接收、库房入库、对外出库及检验发货确认、改量/作废、丢失和加急。
- 仍为单后端实例、单 Uvicorn worker；多个 worker/实例需先接入跨进程事件通道。直接 SQL 或独立导数进程不在当前通知机制内，维护后需重新连接。
- 已配套发布前后端；旧浏览器页面需重新加载一次以载入本次程序，之后业务更新自动推送。不需要数据库迁移，不清理或补写演示数据。
