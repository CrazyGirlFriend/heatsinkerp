# 全厂总览与大屏（2026-09-12）

> 阶段快照：以下保留 2026-09-12 的设计和验收过程。当前 `/` 已改为库存卡片与 SSE 推送，图表移至 `/factory-analysis`，机器人大屏独立位于 `/factory-live`。旧库存表述、分页和“未部署”状态不代表当前版本；当前操作见 [用户使用说明](phase-1-user-guide.md)，库存公式见 [一期物料流转口径](phase-1-material-transfer.md)，发布状态见 [服务器部署](server-deployment.md)。

本次仅更新本地演示，不发布服务器、不清理或重建业务数据。沿用 Vue 3、Element Plus、ECharts、Axios 与 FastAPI；正式数据库仍为 MySQL，本地演示沿用隔离 SQLite。

## 入口与页面职责

`/` 为全厂总览，侧栏为独立一级入口，不增加第三层导航。管理员普通登录后进入该页，班组长仍默认进入绑定班组；安全的显式站内跳转优先。两类账号均可查看全厂总览，仍受站点访问锁和登录保护。

全厂页用于观察整体状态，不承载录入、接收或出库操作。班组库存柱条可跳到对应班组的流水号台账；流水号的批次详情继续由既有抽屉展示。原班组“数据分析”“流水号台账”“材质归类”保持分开。

## 四项关键数字

| 指标 | 口径 |
| --- | --- |
| 全厂账面结存 | 八个正式班组已入账来源的剩余量之和；包含待转出占用。另示可用量。 |
| 待交接物料 | 当前待确认内部转料及库房对外出库、检验发货；CK 整批仅计一个批次，各待确认明细量只加一次。 |
| 近期入库 | 近 7/30 天已登记的库房手工入库，不累加内部接收。 |
| 近期对外出库 | 已确认的库房对外出库与检验发货之和，另示检验发货量。 |

待交接中的未建库存首次手工转料不一定属于已入账结存；不可用“全厂结存减去全部待交接”推算可用。可用量由来源台账计算。账面位置也不等于实物实时定位：待下序确认的料可能已离开原班组。

## 三个主题、九张图表

四项关键数字固定在顶部，中部每次展示一个主题的三张图，不把九张图压缩到同一屏。

| 主题 | 图表 | 内容 |
| --- | --- | --- |
| 全厂态势 | 班组库存分布 | 八班组可用量与待转出占用；点击有效班组进入流水号台账。 |
| 全厂态势 | 全厂对外收发 | 库房入库、库房对外出库、检验发货的每日确认量；内部转料不计入。 |
| 全厂态势 | 物料类型 | 当前结存的成品、半成品、余料、废品等构成，不是材质分类。 |
| 库存分析 | 流水号库存排行 | 跨班组汇总同一流水号的账面结存，再按所选件数或重量取前八名。 |
| 库存分析 | 材质库存排行 | 跨班组汇总同一材质的账面结存，再按所选单位取前八名。 |
| 库存分析 | 库存停留 | 剩余来源批次自接收后的时间，不足 1 天、1–3 天、3–7 天、7 天及以上。 |
| 交接与异常 | 待交接时长 | 按登记时间区分内部待接收和对外待确认，不按上下序各加一遍。 |
| 交接与异常 | 丢失趋势 | 每日实际登记丢失，显示周期合计；不包含转废。 |
| 交接与异常 | 对外出库构成 | 所选周期内已确认的库房对外出库与检验发货，分别展示。 |

重量（kg）和件数可切换。近 7/30 天只影响收发、丢失事件，当前库存、排行、类型和等待不受近期范围截断。每日边界按工厂配置时区，收发按实际接收/出库确认时间，不按原单创建时间。

范围为库房、轧制、退火、研磨、线切割、雕刻、电镀、检验八个稳定编码，而非硬编码数据库 ID。停用班组的既有库存仍计入并提示；缺失班组显示未配置、提示汇总范围不完整。未纳入台账的历史接收单独提示，不猜测期初库存。不提供尚未采集的产量、良率或工艺完成率。

## 大屏布局与运行

- 普通首页保持浅色 Element Plus 风格；“大屏模式”通过浏览器 Fullscreen API 进入独立深色布局，隐藏应用导航和顶部栏。退出按钮或 Esc 返回，点击班组图表也先退出全屏再跳转。
- 以 16:9、1920×1080 为基准：顶部四项数字，中部三张图按 5:4:3 分配宽度，底部近期批次；统一间距，图表区域随可用高度伸展。保留呼吸空间，不用大块空标题区。
- 普通桌面与窄屏分别适配；窄屏采用两列或单列纵向浏览，不把整张大屏等比例缩成小字。4K 电视和实际观看距离尚未现场验收，不能仅凭显示器分辨率判定文字可读。
- 默认 60 秒刷新；可关闭自动刷新、手动刷新。页面隐藏或正在请求时不追加定时请求；离开页面清理刷新和轮播计时器、图表及监听。刷新时保留已有图表，不清成空白再加载。自动刷新与轮播是独立开关。
- 显示成功取数时间。刷新失败保留上次数据并明确提示；首读失败展示错误和重试，不伪装成全零。网络恢复后下次刷新更新，登录或访问锁失效仍按既有权限流程处理，不绕过登录。
- 普通首页默认手动切页；进入大屏后每 20 秒切换主题。支持上一屏、下一屏、暂停/播放和锁定当前屏。主动切页会暂停轮播；“锁定当前屏”只停止换屏，不停止图表轮显和近期批次切换。
- 班组、流水号、材质及物料类型图每 4 秒轮显有效数据，下方直接显示对应名称、件数和重量，不依赖悬停。换屏采用短淡入淡出，避免持续闪烁、粒子背景和固定工艺路线等无业务含义的动画。
- 鼠标停留或键盘焦点进入图表/近期批次区域时暂停轮播；移开后继续。页面隐藏、请求失败时也暂停，不补播后台错过的屏。开启系统“减少动态效果”时改为手动切页，关闭自动轮播和动态过渡。
- 顶部数字只在实际数据变化时从原值平滑更新，不反复从零滚动；切换件数/重量或统计周期不混算过渡。演示数据没有新增时，数字保持不变。

## 近期批次

底部展示最近更新的 12 个批次，每组 3 个，每 8 秒切换。这里是大屏摘要，不替代管理列表的每页 20/50/100 条分页。点击批次号进入现有扫码详情页；从大屏跳转会先退出全屏并停止轮播，不自动执行接收或确认。

CK 多明细先聚合为整批，再按更新时间排序；数量和重量只汇总未作废明细。部分确认显示“部分接收”，全部作废显示“已作废”，并保留单据记录。无 CK 的独立 TL 单按自身批次展示。摘要显示的是最新状态，并非完整审计事件流；不会把刷新渲染当作新转料，也不补造历史动态。完整修改和交接细节仍在批次详情。

长期电视展示还需现场安排合适的浏览器缩放、显示器休眠、网络、账户管理与物理访问控制。本期没有新增专用只读展示账号或免登录公开链接，也没有自动修改电脑电源设置；不要把管理员或班组长会话当成公开信息屏。

## 实现与验证

新增只读 `GET /api/factory-overview?days=7|30`，复用来源台账余额、时区和统计工具。未修改数据库结构、迁移或业务写入流程。MySQL 实际数据量下的性能和长时间电视运行仍需部署现场验收，本地 SQLite 测试不代表生产性能。

本轮后端完整测试 140 项、前端完整测试 276 项通过；最终类型检查、生产构建及 11 项轮播相关回归测试通过。新增覆盖全厂库存排行分组/单位排序、近期整批聚合及部分确认、20/4/8 秒轮播、锁定/手动切页、悬停/后台/失败暂停、数字动画和卸载清理。后端有既有 AnyIO 弃用警告；构建中共享 ECharts 分包约 565 KB，仍有超过 500 KB 的提示。图表字体使用 Canvas 有效的字体族，避免 `inherit` 使字体回退为 10 px。

本地只读核对：库房入库 19,210 件 − 对外出库及发货 36 件 − 丢失 192 件 = 账面结存 18,982 件。待交接 172 个批次、1,684 件；可用 17,298 件。演示历史集中在一天，趋势中的集中峰值是真实演示记录，不填造多日波动。原数据仍为 433 条物料记录、376 个出库批次、192 条丢失记录。
