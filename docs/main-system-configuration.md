# 主系统对接配置

状态：2026-09-15 本地实现，尚未部署；真实主系统认证方式与接口仍待确认。

## 页面操作

入口：系统管理员登录后，进入“系统设置 → 主系统对接”。班组账号无权读取、修改或测试配置。

1. 填写主系统 HTTPS 地址、访问令牌和请求超时。地址必须在部署管理员设置的白名单内。
2. 保存配置。令牌输入框随后清空，只显示“已保存”；留空保存表示保留原令牌，更换地址必须重新填写令牌。
3. 输入真实样例流水号，点击“测试查询”。测试使用已保存配置，停用状态也可以测试；只读取资料，不生成入库、出库或转料记录。
4. 核对返回资料。通过真实联调后再启用资料查询。停用不会影响已有库存和内部班组转料。

保存后立即生效，不用重启。若其他管理员已修改配置，页面会要求重新加载，避免覆盖他人修改。

## 认证约定

当前支持主系统签发的专用只读 Bearer Token。只填写令牌本身，不包含 `Bearer ` 前缀。后端通过 HTTPS 请求主系统时自动附加：

```http
Authorization: Bearer <访问令牌>
```

这不是本物料系统的登录密码。浏览器提交令牌给本系统后端用于保存，不直接持有令牌访问主系统；配置读取接口不返回令牌明文或密文。生产环境访问本系统的管理页面也必须使用 HTTPS，避免首次提交凭证在网络中明文传输。

数据库只存 Fernet 加密后的令牌；加密密钥仅放服务端环境，必须限制其文件访问权限。配置接口校验错误不回显提交的令牌。测试显示令牌失效、权限不足等明确结果，不透传主系统的原始错误响应。

当前没有 OAuth 登录/令牌自动刷新或 AppKey 签名功能。对方应提供：认证文档、凭证获取方式、有效期、读取权限范围，以及是否限制出口 IP。确认后按其实际规范接入，不假定任意 API Key 都能作为 Bearer Token 使用。

## 部署前置项

此版本增加 `cryptography` 依赖，需更新后端运行环境/镜像；执行数据库迁移至 `20260915_0012`（正常部署使用 `alembic upgrade head`），新增单行配置表，不改变库存记录。不要仅替换静态前端文件。

服务端 `.env` 新增：

```dotenv
MAIN_SYSTEM_CONFIG_KEY=部署时生成的Fernet密钥
MAIN_SYSTEM_ALLOWED_ORIGINS=https://已确认的主系统域名
```

密钥应使用 `cryptography.fernet.Fernet.generate_key()` 安全生成，每个环境独立，勿将示例文字当密钥。与数据库分开安全备份，不写入代码仓库、页面或日志。丢失密钥将无法解密已存令牌；更换密钥后需重新录入令牌，本期未实现自动密钥轮换。

白名单用逗号分隔，校验协议、域名和端口；页面不能自行扩大白名单。原 `MAIN_SYSTEM_BASE_URL` 也视为可信地址。初次数据库没有配置时，继续使用 `MAIN_SYSTEM_BASE_URL`、`MAIN_SYSTEM_TOKEN`、`MAIN_SYSTEM_TIMEOUT_SECONDS`；页面保存后以数据库为准。
