# 库房仓位与批次占用

更新：2026-09-28。本轮物料关联仓位已完成本地开发；新增迁移 `20260928_0024`，尚未发布。上轮“仓库管理、单批独占及填写时锁定”线上版本为 `20260928T063236Z`，程序提交 `568284a`，迁移版本 `20260928_0023`。以下使用规则对应本轮新版，不代表线上已更新。

## 使用

- 库房账号或管理员在“班组工作台 → 库房 → 仓库管理”新增、修改、停用仓位。有料时允许改名，不能停用；正在被填写中的表单选择时暂不能修改。
- 上游转料单转入库房时，每一行物料可以选一个空闲仓位；库房手工入库也可以选择。单据未选时，库房单批签收仍可补选。
- 仓位可留空。无空仓时提示“暂无空闲仓位，可不填写”。不能在单据中随意输入未建档仓位。
- 一个仓位只接受一个入库批次。每条转料明细都有独立批次号，批量提交也不能让两条明细共用仓位。
- 入库记录、批次单据及打印保留入库时的仓位名称。库存来源、流水号库存详情和出库选料显示**当前仓位**；不会将历史仓位当作当前位置，也不会继承到下一班组。

## 库房选料转出及退回

- 库房在“新建出库”中勾选已有库存，自动带出流水号、材质、类型，默认填入可转出的全部件数和重量，也可部分转出。再选择下序班组和接收业务。库房不显示加工件数变更和类型转换；其他加工班组原有流程不变。
- 勾选三条物料，生成三个独立批次、三个条码。可以合并打印在一张纸上，不会产生一个包含多种料的公共批次号。
- “仓库管理 → 仓位物料”提供查看物料、转出入口。仓位随物料实际移出而释放，没有绕过库存的“清空”按钮；系统管理员可管理位置，但不能代替班组账号提交出库。
- 未签收前，上序可修改或作废。退回数量自动进入“未分配仓位”，不恢复旧位置，也不影响后来使用旧仓位的其他批次。
- 例：A 仓位原有 100 件 / 100 kg，转出 30 件 / 30 kg，A 剩 70 件 / 70 kg；再将转出改成 20 件 / 20 kg，A 仍是 70 件 / 70 kg，退回的 10 件 / 10 kg 显示为未分配。修改不是把整批剩料移出 A。
- “仓库管理 → 未分配仓位”可以查询批次并安排空闲仓位；库存明细的“更多 → 有未分配仓位的物料”可以筛出相关库存。未分配只是位置未指定，不会减少库存，也不妨碍正常转出。
- 同一批次有多个实际位置时，转出按仓位编号顺序扣除已安排物料，再扣除未分配物料。件数、重量独立扣除，不按比例推算或自动换算；界面显示本次出库数值，后台再次校验。
- 已转出待签收的数量仍归上游，但已从可转出量扣除，不能重复出库。确认后不再重复扣仓位。

## 锁定与释放

| 情况 | 仓位状态 |
| --- | --- |
| 填写时选中仓位 | 立即锁定，其他表单和账号不可再选 |
| 未提交，取消／关闭表单／清空选择 | 释放临时锁 |
| 换仓位 | 新仓位锁定成功后释放原仓位；选择失败保留原选择 |
| 未提交满 10 分钟 | 自动到期，提示重新选择；继续填写或续锁不会延长上限 |
| 断网／浏览器异常退出 | 最多 3 分钟失联到期，且不超过原 10 分钟上限 |
| 提交转料单成功，待库房签收 | 由单据占用，关闭页面不释放 |
| 库房签收／手工入库成功 | 有料，占用仓位 |
| 尚未签收的入库单作废 | 释放目标仓位 |
| 内部部分转出 | 原仓位只保留尚未移出的数量和重量 |
| 内部全部转出，尚未签收 | 原仓位立即释放；待签收仍归上游，但不能再次转出 |
| 减少尚未签收的出库数量／作废出库 | 恢复库存至未分配仓位，不占回旧仓位 |
| 新建对外出库 | 提交即完成，扣减当前仓位；全部移出时释放 |
| 历史对外待确认单据 | 保持原占用，确认实际出库后才释放 |

选仓位后显示“已锁定 · 09:59 后释放”，剩余 1 分钟变为橙色提醒。提交成功后临时锁转换成单据占用，不受填写倒计时影响。

既有数据不会被迁移改写：历史仓位名称会进入管理目录。如果旧仓位已有多个批次，只展示真实记录，禁止再放入新批次，直到全部清空。

## 后端约束

- `warehouse_locations` 保存仓位目录、版本号、持锁账号、表单随机键、短期有效时间和固定到期时间。
- `warehouse_placements` 保存仓位与来源批次的当前实际数量、重量，与单据上的历史名称分开。当前物料为在库可用量加历史对外待确认量，不含内部转出待签收；未分配量为当前物料减去已安排仓位的数量。
- 位置扣减与库存写入使用同一事务。恢复库存不新增位置记录；数量和重量同时为零才释放仓位。内部签收不重复扣减。库房不能在转出时变换原物料类型。
- `POST /api/warehouse-locations/{id}/placement` 将指定来源的未分配件数、重量放入空仓。先锁来源批次，再锁仓位；检查版本、空闲状态和剩余可安排量。并发竞争、重复安排和超量请求拒绝，不修改业务库存总量；记录审计并通过原实时通道通知。
- 来源库存接口增加 `warehouse_positions`、`physical_quantity/weight`、`unassigned_quantity/weight`；库房来源列表及分类库存支持 `location_status=unassigned`。
- `POST /api/warehouse-locations/{id}/reservation` 选中／续锁；`DELETE` 同一路径取消。旧表单迟到的释放请求不能清掉新表单或已提交单据的占用。
- 管理目录 `GET/POST /api/warehouse-locations`、`PATCH /api/warehouse-locations/{id}` 仅库房账号和管理员可用，修改检查版本并记录审计。
- `GET /api/team-materials/{team_id}/warehouse-locations` 仅返回可选仓位，以及当前选择用于回显的仓位。
- 入库、转料明细和补选签收同时传 `warehouse_location` 与 `warehouse_location_reservation_key`。后台在同一事务中检查持有人、有效期、单批占用并保存单据；界面判断不能绕过后端限制。
- 已提交单据的仓位不能直接更换；待签收单据需要作废重建。历史件数、重量、库存归属和批次关系保持不变。
- 发布前备份并停止旧写入服务，执行 `alembic upgrade head` 后启动新版服务；不能混用不维护新位置表的旧写入节点。0024 按当前库存初始化实际占用，历史一仓多批不改写，全部移出后才恢复单批独占。迁移重复执行不会将已退回的料放回历史仓位。发生问题优先修复或恢复完整发布前备份，不能仅降级代码继续写入；不提供会丢失位置的自动降级。
