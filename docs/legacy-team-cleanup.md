# 旧班组清理

正式班组为库房、轧制、退火、研磨、线切割、雕刻、电镀、检验。转废由库房管理，发货属于检验；两者不独立建班组。接口拒绝 `scrap` 班组类型及旧班组编码、名称，管理页面不再显示“转废班组”类型。废料、废屑等物料分类和现有出入库功能不变。

服务器旧数据中还保留 `FACTORY-SCRAP` 和 `FACTORY-SHIP`：前者关联一条旧报工的报废去向，后者关联两条旧工序及一条旧工艺路线。当前账号、转料和库存没有引用这两个班组，旧引用导致普通删除接口拒绝删除。

维护程序：`backend/app/retire_legacy_teams.py`。在停写并备份数据库后，用当前后端环境执行：

```sh
python -m app.retire_legacy_teams --actor-id <管理员ID>
python -m app.retire_legacy_teams --actor-id <管理员ID> --apply
```

默认预演并回滚；`--apply` 才提交。必须指定有效管理员，程序严格核对旧班组及接收班组的编码、名称和类型，检查数据库所有指向班组的外键。只允许上述历史归属调整；存在账号、库存、当前流转或其他引用时整笔回滚，不能用它合并正在使用的班组。

调整历史记录的班组 ID 和班组名称，保留记录本身、数量、原因、工序名称和业务时间；原归属和受影响记录 ID 记入管理审计。两条班组删除、历史归属调整、审计和目录变更通知一并提交。重复执行不会再次调整或产生删除审计。

验证包括历史记录保留、原归属审计、重复执行、遇到其他引用整体回滚，以及接口禁止新建和改名恢复旧班组。线上执行另做停写前后逐表摘要核对，确认当前物料、库存、账号等表未变。
