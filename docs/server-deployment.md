## 访问保护

入口为纯白页面，默认只显示中央锁图标。点击锁后展开口令输入，按回车或右侧箭头提交；按 Escape 可收起。验证通过后才显示原有账号登录页。口令只保存在服务器 `.env` 的 `SITE_ACCESS_PASSWORD` 中，不写入前端代码。

后端使用 12 小时有效的 HttpOnly、SameSite=Lax 签名 Cookie 校验访问资格。没有正确 Cookie 时，登录接口、业务接口、已有账号令牌及接口文档都不能绕过访问锁。更换 `SITE_ACCESS_PASSWORD` 或 `SITE_ACCESS_SECRET` 后，旧 Cookie 会失效。仍然需要正常管理员/班组账号登录，站点口令不替代账号权限。

每个来源 5 分钟内最多 10 次错误尝试，此外有进程级总限额。前端 Nginx 丢弃请求方自带的 X-Forwarded-For，再将客户端地址传给专属网络内的后端。

当前 IP 入口为 HTTP，口令、Cookie 与业务数据在网络传输中不加密，仅适合演示验收。正式使用应绑定域名、配置可信 HTTPS，将 `APP_ORIGIN` 改为 HTTPS 地址、`SITE_ACCESS_SECURE_COOKIE` 改为 `true` 后重建后端容器；同时更新前端转发 HTTPS 协议的配置。HTTP 环境不要设 Secure=true，否则浏览器不会在 HTTP 请求中发送访问 Cookie。

## 配置与发布注意

首页实时推送版本需要配套发布前后端，保留单个后端容器和 `--workers 1`，否则进程内提交事件不能跨 worker 传递。Nginx 必须关闭 SSE 缓冲；如增加上层代理也需保持流式转发。此功能已随 `20260914T092908Z` 上线，详见 [首页库存实时推送](inventory-realtime.md)。

数据库、管理员初始密码及签名密钥均使用部署时新生成的随机值；不要沿用开发默认数据库密码。管理员初始密码只在尚无有效管理员时使用，修改环境变量不会重置已经存在的管理员密码。

发布时先将源码放入新的 releases 子目录，设置对应 `RELEASE_TAG`，构建并验证后再切换 current。保留旧源码与镜像，数据库升级前做备份。不要使用 `down -v`，该操作会删除 MySQL 数据卷。回退镜像不等于回退数据库，数据库迁移需单独确认兼容性。

macOS 打包源码时设置 `COPYFILE_DISABLE=1` 并排除 `._*`、`.DS_Store`，避免 AppleDouble 附带文件进入 Linux 发布目录。前后端 `.dockerignore` 也排除这些文件，防止 Alembic 将 `._*.py` 当成迁移导入。

前端单独发布时可设置 `FRONTEND_RELEASE_TAG`，其优先于 `RELEASE_TAG`；后端仍使用 `RELEASE_TAG`。完整前后端升级时要同时更新两者，或删除前端单独覆盖，避免继续使用旧前端。应用前端更新使用 `up -d --no-build --no-deps frontend`，不重启后端/数据库。
