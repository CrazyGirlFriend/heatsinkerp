# 首页库存实时推送

## 本次范围

全厂库存首页 `/` 使用服务端主动推送；已移除原先每 10 秒查询库存的计时器。后续已完成确认效果图及浅白紫样式落地，当前共用规则见 [界面一致性约定](ui-style-guide.md)。本文记录首页首次推送发布；机器人大屏与班组台账扩展已随 `20260914T152856Z` 上线，见 [台账及大屏实时推送](workspace-realtime.md)。

## 更新链路

业务事务提交成功 → 唤醒在线订阅 → 按原库存口径计算完整汇总 → SSE 推送 → 首页直接更新数字。

- 覆盖库房入库、班组转出、下序接收、对外出库/发货确认、修改/作废、丢失登记、流水号加急，以及班组配置变化。
- 内部转料仍是提交即减上序在库、增加内部在途；下序接收后增加下序在库并减少在途。不改变存量数据和库存公式。
- 只在数据库事务提交后通知；失败回滚和幂等重放不发布业务变化。多条明细合并为一次事务通知，突发变更可合并读取最新状态。
- 首次连接与重新连接都发送完整当前快照，断线期间的最终状态不会遗漏；这不是逐事件审计回放。
- 没有变化时不重复查询库存，不强迫数字滚动。15 秒心跳只保活并复核访问权限；前端 45 秒未收到任何字节会断开旧连接并重连。
- 断线保留上次成功数据，明确显示连接中断；按 1、2、4、8、15 秒退避重连。成功收到快照后恢复“实时同步”。
- 暂停只暂停动画，不暂停数据。页面隐藏时关闭连接，恢复可见时接收新快照；卸载时释放连接、读流和重连计时器。
- “刷新”保留为手动重新连接入口，正常更新不依赖该按钮。

## 接口与权限

`GET /api/factory-overview/stream`，响应 `text/event-stream`；`inventory` 事件直接携带与现有全厂总览一致的 JSON 汇总。

使用 Fetch 流式接收以携带既有 `Authorization` 请求头和访问锁 Cookie。令牌不放在 URL，不提供免登录公开推送。未登录/无访问锁仍被拒绝；已有连接在推送前和心跳时复核权限，失效时发送 `auth-expired` 或 `access-required` 并关闭。

## 部署边界

- 当前为单后端实例、单 Uvicorn worker，提交通知使用进程内事件。两个 Dockerfile 均显式固定 `--workers 1`，与现有部署拓扑一致。不要直接横向扩容或增加 worker；扩容前需加入跨进程消息通道。
- MySQL 和业务表不变，不新增 Redis、数据库迁移或定时扫描库存任务。直接 SQL、独立进程导数不产生本进程通知；完成此类维护后需要重新连接首页，不将其宣称为已支持的在线业务推送。
- Nginx 禁用代理缓冲，接口同时返回 `X-Accel-Buffering: no` 和禁止缓存响应头。上层代理如存在，也须保持流式转发；推送需要配套发布前后端。
- 已随 `20260914T092908Z` 配套部署前后端；线上保留单实例、单 worker，数据库未迁移或重置。

实现依据：[FastAPI StreamingResponse](https://fastapi.tiangolo.com/advanced/custom-response/#streamingresponse)、[SQLAlchemy 事务事件](https://docs.sqlalchemy.org/en/20/orm/session_events.html)、[SSE 格式与连接管理](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)。
