# 一期导航与现场入口速查（2026-09-12）

侧栏最多两级：首页“全厂总览”为独立一级入口；“物料流转”“班组”“系统设置”为一级分组，八个正式班组统一放在“班组”的二级菜单。展开、收起只改变显示方式，不改变菜单归属。系统设置仅管理员可见。

业务列表默认每页 10 条，可选择 20、50 或 100 条，增加行数后向下滚动整页查看；数据不足一页时显示实际数量，不补空数据。选料弹窗保留独立滚动与分页。转料单的详细规格、原单信息及审计记录集中在详情中。

| 要做什么 | 页面入口 | 操作角色 |
| --- | --- | --- |
| 查看全厂关键数字、图表或进入全屏大屏 | 全厂总览 → 大屏模式 | 管理员、班组长只读 |
| 库房自行登记实物入库 | 库房 → 手工入库 | 仅库房班组长 |
| 查看手工入库原单 | 库房 → 入库记录 | 管理员、班组长只读；原单入账后锁定 |
| 查看班组收发、库存、等待和丢失图表 | 对应班组 → 数据分析 | 管理员、班组长 |
| 一行一个流水号查看完整余额及批次明细 | 对应班组 → 库存明细 | 管理员、班组长 |
| 查看各材质可用件数、重量 | 对应班组 → 材质归类 | 管理员、班组长 |
| 查看发往本班的来料 | 对应班组 → 待接收 | 管理员、班组长；接收操作仅本班 |
| 从库存单批或批量出库 | 对应班组 → 新建出库；或库存明细 → 流水号详情 → 来源余量 | 本班组长 |
| 查看整批明细、一个条码并打印汇总单 | 对应班组 → 出库记录 → 整批详情 | 管理员、班组长 |

| 发货并确认 | 检验 → 新建出库 → 出库记录 | 仅检验本班组长 |
| 登记、查看来源批次丢失原因 | 库存明细 → 流水号详情 → 来源余量 → 登记丢失；丢失记录 | 登记仅本班组长 |

| 发起本班组转料 | 转料记录 → 新建转料 | 班组长 |
| 扫描条形码并核对转料 | 物料流转 → 扫码接收 | 管理员、班组长 |

| 修改或作废尚未确认的转料 | 转料记录 → 打开详情 | 发起班组长 |
| 按流水号查看全部交接和位置 | 物料流转 → 流水追踪 | 管理员、班组长 |
| 新增、修改、停用班组 | 系统设置 → 班组管理 | 管理员 |
| 新增、修改、停用班组长账号 | 系统设置 → 班组长管理 | 管理员 |

管理员只维护班组与班组长，可以只读查看转料和追踪，但不能代替班组发起、修改、作废或确认转料。班组长账号绑定一个有效班组，登录后该班组自动作为转出班组，也只能确认接收班组为本班组的批次。

批量出库一批一个 CK 号和 Code 128 条码，一批只对应一个转出班组、一个去向。扫码查看所有流水号、材质、类型、件数和重量，一次确认全部待确认明细；打印一份单联 A4 汇总单，常规一张纸，内容多时完整续页。独立手工转料、入库单和旧 TL 条码仍可查询，已有关联的 TL 可打开所属整批，不再逐行打印。蓝牙扫码枪作为 HID 键盘输入编号并回车，前端不使用摄像头或蓝牙接口。

待接收时仅发起班组可修改或作废。接收班组核对原单后执行整批确认，不重新填写数量或重量；确认后记录永久锁定。实物与单据不一致时不确认，由发起班组先修改原单。同一流水号可有多张转料单，流水追踪按时间展示完整交接轨迹和最近一笔状态，不校验产品工艺或固定班组顺序。

正式班组为库房、轧制、退火、研磨、线切割、雕刻、电镀、检验。每个班组有库存明细、待接收、出库记录、丢失记录、材质归类、数据分析六个基本工作区，库房额外提供手工入库及入库记录；库房包含转废，检验包含去毛刺和发货职责，不另设这三个班组。库存明细一行一个流水号，批次余量及收发记录在详情中查看，不再保留重复的台账页签。图表与库存明细为独立页面，点击图表跳转到对应筛选结果。详见 [用户指南](phase-1-user-guide.md)。

库房手工入库不依赖公司主系统、不选择上下序，提交直接形成库存；内部班组转回库房则仍走待接收确认。入库批次可以出库、登记丢失并沿流水号追踪，不重复做一次“接收”。

旧产品工艺、工单、报工、班组产量页面和后端业务接口已删除，仅保留少量旧页面 URL 重定向。2026-09-11 已按用户要求准备业务数据清空工具；只有在停写、备份和明确确认数据库后执行才删除业务记录，日常启动和升级不会清空数据。账号、班组、迁移版本与条码计数器保留。
