# 一期导航与现场入口速查（2026-09-27）

2026-09-27 更新：班组导航恢复两级“班组工作台 → 班组”。库房、轧制、退火、研磨、线切割、雕刻、电镀、检验直接点击进入库存明细，不再展开第三层功能。库存明细、待接收、出库记录、丢失记录、材质归类、收发历史放回班组页面顶部横向导航；库房增加入库记录。窄屏可横向滚动功能导航，侧栏高度不足时内部滚动，不隐藏班组。

展开样式：仅一级菜单保留展开箭头，班组不再带箭头。侧栏高亮当前班组，页面内高亮当前功能；切换功能不会改变侧栏的展开状态。保留原有浅灰绿主题、焦点提示和减少动态效果支持。收起整条侧栏后，可通过浮出菜单直接选择班组。

侧栏状态统一：所有业务页（包括首页）共用 `FactorySidebar.vue` 的同一棵菜单树，不再为首页切换菜单层级或字体。一级入口固定为全厂总览、班组工作台、流转查询、系统设置（仅管理员）。`teamWorkspaces.ts` 定义八个班组及页面内功能；实际班组 ID、配置状态来自班组目录接口。共用 `TeamWorkspaceShell` 渲染横向功能导航，不复制八套页面。

展开状态由 Pinia `sidebar` store 维护，按账号在本机保存折叠偏好、一级展开分支和对应路由路径。旧的班组展开记录自动忽略，旧的带功能参数页面记录归并为班组路径。刷新页面、收起再展开侧栏保留手动选择；搜索、分页、切换班组内功能和目录刷新不会强制改变侧栏分支，切换班组或其他页面时才定位对应入口。这些偏好不参与权限校验。顶部标识和底部账户区固定，中间菜单独立滚动；溢出时显示可点击的上下滚动提示。手机仍使用抽屉导航，不继承桌面的图标收起模式。

页面顶部仅恢复一行功能导航，不恢复大标题、顶部统计卡片、库房统计下拉或独立操作行。新建、扫码、刷新及班组设置继续放在当前页面的搜索 / 表格工具栏。桌面展开侧栏时不显示顶部日期与面包屑，账号菜单、退出登录和大屏入口固定在侧栏底部。收起侧栏或使用手机时保留简短的当前页面提示，手机另有导航按钮。功能切换继续使用原 `tab` 查询参数；刷新、返回和旧链接有效，点击当前功能不会清空筛选，浏览器后退恢复原查询条件。待接收数量显示在页面内功能名称旁，复用当前页面实时数据，不额外请求八套统计。管理员 / 班组账号原有查看、操作权限不变，系统设置仍仅管理员可见。

业务列表默认每页 10 条，可选择 20、50 或 100 条，增加行数后向下滚动整页查看；数据不足一页时显示实际数量，不补空数据。选料弹窗保留独立滚动与分页。转料单的详细规格、原单信息及审计记录集中在详情中。

管理员只维护班组与班组长，可以只读查看转料和追踪，但不能代替班组发起、修改、作废或确认转料。班组长账号绑定一个有效班组，登录后该班组自动作为转出班组，也只能确认接收班组为本班组的批次。

批量出库一批一个 CK 号和 Code 128 条码，一批只对应一个转出班组、一个去向。扫码查看所有流水号、材质、类型、件数和重量，一次确认全部待确认明细；打印一份单联 A4 汇总单，常规一张纸，内容多时完整续页。独立手工转料、入库单和旧 TL 条码仍可查询，已有关联的 TL 可打开所属整批，不再逐行打印。蓝牙扫码枪作为 HID 键盘输入编号并回车，前端不使用摄像头或蓝牙接口。

待接收时仅发起班组可修改或作废。接收班组核对原单后执行整批确认，不重新填写数量或重量；确认后记录永久锁定。实物与单据不一致时不确认，由发起班组先修改原单。同一流水号可有多张转料单，流水追踪按时间展示完整交接轨迹和最近一笔状态，不校验产品工艺或固定班组顺序。

正式班组为库房、轧制、退火、研磨、线切割、雕刻、电镀、检验。每个班组有库存明细、待接收、出库记录、丢失记录、材质归类、收发历史六个基本工作区，库房额外提供手工入库及入库记录；库房包含转废，检验包含去毛刺和发货职责，不另设这三个班组。库存明细按流水号组织，区分物料分类、用途和来源，批次余量及收发记录在详情中查看，不再保留重复的台账页签。详见 [用户指南](phase-1-user-guide.md)。

库房手工入库不依赖公司主系统、不选择上下序，提交直接形成库存；内部班组转回库房则仍走待接收确认。入库批次可以出库、登记丢失并沿流水号追踪，不重复做一次“接收”。

旧产品工艺、工单、报工、班组产量页面和后端业务接口已删除，仅保留少量旧页面 URL 重定向。2026-09-11 已按用户要求准备业务数据清空工具；只有在停写、备份和明确确认数据库后执行才删除业务记录，日常启动和升级不会清空数据。账号、班组、迁移版本与条码计数器保留。
