## 承接业务由谁维护、谁选择

- 各班组长登录自己的工作台，点击右侧 **班组设置 → 承接业务**，新增、改名或停用本班组业务。例如检验班组可设置“检验、去毛刺”。现有 `TEAM` 账号即本班组长权限，不新增角色。
- **上序开转料单时选择下序业务**：先选接收班组，再给每行物料选业务。不同流水号、物料类型或业务可分别形成批次，合并到一张打印单中。
- 承接业务与“成品、半成品、板材、废屑”等物料类型是两类独立信息；也与主系统资料里的“用途类别”无关。
- 下序仍只接收确认；确认后上序不能改单。业务改名或停用不会改写旧单的名称快照。
- 未配置业务的班组，新单暂归“未分类”，兼容现有接口。一旦配置过业务，新开单必须选择启用的业务；全部停用时须先启用一个。历史未分类单据不会补造业务。
- 业务不定义工艺路线，也不增加报工、检验完成等生产状态。不改变原有库房出库和检验发货权限。

待接收、入库、出库记录的物料信息显示承接业务，通用搜索支持按原单业务名称查找；库存明细可单独选择“本班组业务”搜索。业务改名、停用后仍按原单名称查询。班组设置中的改名、启停均需点击该行“保存”；仅本班组账号可修改，配置变动保留操作人和前后值审计。

本次沿用 `TeamPurpose`、`purpose_id`、`purpose_name` 和现有接口，不新增数据库迁移。

## 首次启用时录入库存

1. 系统管理员进入 **系统设置 → 班组管理 → 期初授权**，开启指定班组录入权限；管理员不代替班组提交库存。
2. 班组长进入 **本班组工作台 → 班组设置 → 期初库存**，填写流水号、材质、规格、物料类型、件数和重量，可选本班组业务、备注。流水号按文本保存，保留前导零。
3. 可增加多行、保存本机草稿；草稿不入账、不上传服务器、不跨账号或班组共用。
4. 整批核对后点击 **确认期初入账**。所有行在一个事务中入账，每行独立批次和 Code 128 条码；失败整批回滚。随后可合并打印。
5. 入账立即增加本班组库存，并推送更新其他库存视图。来源为“期初库存”，没有上序，也不产生待接收。

每个班组仅能完成一次初始化，提交成功自动关闭授权。已存在正式入账历史的班组不能再把当前库存重复叠加为期初库存，即使余额已清零也不能重新初始化。没有清库或覆盖库存功能；当前演示数据保留。件数可为零（如废屑），但件数和重量不能同时为零。

重复网络请求使用同一幂等键返回原结果，不重复加库存；同一键换内容会被拒绝。已入账记录不可直接改写或删除，后续仍通过正常收发、丢失记录反映变动。

## 本班组：收发历史

入口：**班组工作台 → 对应班组 → 收发历史**。输入完整流水号，按本班组接收时的业务分组。

- 单一时间画布按业务、来源批次分轨；同业务的不同来源仍是独立细线。横轴是实际时间，分支表示该来源的转出、丢失、改量或作废退回，末端表示图示期末结存。
- 实心为收进、空心为转出、红叉为丢失；事件和留存同时显示件数与重量。密集节点可通过查找入口选取，点击查看完整批次。
- 可按某天或日期区间查询；区间开始前的余额作为期初，不把原收进量当作区间期初。支持滚轮缩放、平移、全屏、绘制重播和动画开关。
- 班组页不再提供全链路切换；全链路仅管理员从独立入口查看。

计算口径：

- 接收确认后入账，期初库存单独记为期初入库事件。
- 上序开单即扣减，不等下序确认；下序确认不会再扣一次上序库存。
- 出库修改按差额增减；作废退回占用；丢失单独扣减。
- “当前未转出”是当前结存，不假定生产中、加工完成等未登记状态。
- 本班组以接收时的业务归类。例如收料为“去毛刺”、转给下序选“发货”，本班组的转出仍归“去毛刺”，下序接收后才进入其“发货”分组。
- 日期限制事件范围，曲线起点包含之前的余额；页面当前结存始终截至现在。历史未纳入库存台账的记录单独提示，不虚构余额。

原 `tab=overview` 打开收发历史。材质归类、全厂首页和机器人大屏保留。

## 全链路：流水号追踪

入口：管理员的 **流转查询 → 全链路追踪**，地址 `/material-trace`。班组账号无入口，前端路由和后端接口均限制管理员访问。

- 根据真实 `source_transfer_id` 连接批次。不同流水号不合并；拆批显示多个分支，回到同一班组仍是新批次节点。不会按班组顺序、单据时间或固定工艺补造连线。
- 期初、外部入库是独立起点；未关联来源的历史转料明确标注。外部回料只有单号备注时仍显示为独立入库，不将备注臆断为批次来源关系。
- 节点主数值为该批转料件数 / 重量，“结存”为本批当前余量；丢失在对应批次标注，点击查原因。对外出库节点显示真实外部去向。
- 实线为已确认，虚线为待确认；作废单可单独勾选查看，不计入有效库存。按接收业务区分颜色，连线进入时逐步绘制。
- 横轴为真实时间、纵轴为班组；画布不再堆叠汇总卡片。全链路数量代表每次转料量，不能相加作为当前库存。
- 查询保留完整来源关系；缩放和底部时间滑块只调整视图，不改变库存。点击批次可突出关联路径并查看完整明细。
- 旧带 `team_id` 的追踪链接转到班组收发页并保留流水号、日期，不自动扩大为全局查询。

两页共享现有库存实时推送，保留未提交的搜索输入；详情打开时暂缓刷新，关闭后同步。图形采用浅色画布与可区分的业务颜色，减少动态效果设置下关闭绘制动画。不修改导航、首页及大屏的主题。

## 接口与迁移

- `GET /api/team-materials/{team_id}/purposes`：读取下序业务；已登录账号可读。
- `POST /api/team-materials/{team_id}/purposes`、`PATCH .../purposes/{purpose_id}`：仅本班组长；更新须传 `expected_version`。名称班组内唯一，删除使用停用。
- `PUT /api/team-materials/{team_id}/opening-stock/authorization`：仅系统管理员，正文 `{"enabled": true/false}`。
- `GET /api/team-materials/{team_id}/opening-stock`：初始化状态。
- `POST .../opening-stock`：仅本班组长，`idempotency_key` + `lines`（1–100 行）。
- 转料新建、修改和批量出库每行增加 `purpose_id`；响应、详情和打印包含冻结的 `purpose_name`。
- `GET /api/team-materials/{team_id}/serial-history?serial_no=000012&date_from=2026-09-18&date_to=2026-09-18`：精确流水号查询，日期按工厂时区解释。
  - `groups` 提供各业务基线、当前结存及变动事件；`team_name` 为本班组名称；`flows` 提供有效批次的方向、业务分组键、来源/去向、件数、重量、状态和批次号。图形字段不额外写库。

- `GET /api/material-trace?serial_no=000012`：仅管理员按完整流水号查询全链路，一次返回全部批次、来源关联、逐批结存、丢失记录、在库分布与数量汇总，无列表分页截断。库存复用现有 `stock_table` 口径，不另存图形统计表。

迁移版本 `20260918_0015` 新增业务、班组设置审计、期初提交表和关联字段，不清理旧数据。上线前备份，再执行 `alembic upgrade head`；MySQL 和 SQLite 均使用固定约束表达式，不依赖数据库返回的 SQL 格式。SQLite 迁移连接应关闭外键强制检查，完成后执行 `PRAGMA foreign_key_check`；不得通过降级丢弃已入账历史。
