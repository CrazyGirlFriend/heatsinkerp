# 扫码直接签收入库

2026-09-28 本地变更，尚未部署。用户确认每扫一批直接签收入库，不再先打开单据查询或二次确认。

- 接收班组账号从工作台点击“扫码入库”进入待接收；库房与生产班组均支持。管理员和其他班组没有此写入入口。
- HID 扫码枪输入独立批次号并发送 Enter，前端读取最新单据版本、检查本班组接收权限，再调用既有 `POST /api/material-transfers/{batch_no}/confirm`。后台事务、幂等、版本检查、签收人和签收时间保持原规则，不增加表或迁移。
- 连续扫码依次处理；正在处理及排队的同一批次去重。已入库、已作废、已退回核对、班组不符和历史 CK 合并号均不会新增入库。网络失败可重新扫描，复用该批次请求键。
- 转入库房使用单据已预留仓位，不覆盖位置；单据无仓位时保留未分配。原列表详情仍可手工核对签收。
- 转料记录页移除扫码查询按钮、弹层、F2 及 HID 监听，只保留普通查单和批次链接。旧扫码书签在登录及刷新身份后将班组账号送到自己的待接收，管理员仍进入普通转料记录；不从 URL 执行签收，不信任旧链接指定的班组或批次。
- 切换账号、班组或离开页面后丢弃尚未提交的扫码；弹窗打开时暂停接收扫码。已发送到后台的签收以后台结果为准。

验证：扫码组件 21 项、工作台 69 项共 90 项通过，覆盖直接签收、连续排队、重复、失败重试、权限变化、错误班组和弹窗暂停。既有后端签收权限与锁定、版本冲突与重试、库房仓位签收 3 项通过；类型检查、修改文件 ESLint 及生产构建通过，保留既有图表分包体积提示。使用模拟 HID 键盘事件验证，未连接实体扫码枪，未修改线上物料。

移除其它扫码入口后，转料记录、路由、扫码入库及相关组件共 73 项回归通过；覆盖旧书签登录跳转、本班组身份刷新、URL 不自动签收、F2/HID 不触发查单、总览批次链接和历史合并记录仍可打开。类型检查、修改文件 ESLint 和生产构建通过。
