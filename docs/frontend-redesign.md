用户选择新的第二张效果图作为落地目标：[soft-workspace-selected.png](design/soft-workspace-selected.png)。以下新规范优先于前面的白底钴蓝和深蓝橙色方案，业务边界继续以一期物料交接为准。

- 四个状态数字来自当前搜索和班组范围内的全部记录，不按当前页条数计算，也不受所选状态限制。切换状态重置分页；搜索或班组变化会更新数量；新建、编辑、作废和接收后重新获取。读取失败显示“—”并允许重试。
- 列表合并批次与流水号、件数与重量，使用文字状态和轻分隔线。宽度不足时隐藏转料人/时间次要列或转为完整记录行。
- 详情用淡紫色流向区域、数量/重量、交接字段和紧凑 Code 128 条码排列；固定操作区与可滚动字段分离。
- 保留待接收流动、接收或作废后静止的状态动画，以及减少动态效果模式。确认接口成功前不提前停止动画。
- 动效仍在选型：已试验单个光点（详情 8px、3.2 秒；列表 4px、3.8 秒），用户未接受。用户进一步提出三个不同颜色的光点依次亮起；现制作蓝、紫、琥珀色柔光接力预览，接收时光晕收起。主应用最终样式待确定，接收成功后停止的状态规则保留。
- 图标继续使用 Element Plus Icons；头像沿用账号首字，未把概念图示例人物照片当成真实用户头像。
- 独立免登录预览和终端 Playwright 流程保留，未使用 Codex 内置浏览器。当前截图与验证记录位于 `output/playwright/soft-workspace/`。

## 上一版方案：白底蓝色、流向动画与并排详情

- 班组筛选放在同一个弹出入口中，仍可独立按转出、接收班组筛选；保留搜索、状态页签、分页和扫码。
- 一期全部业务接口、确认幂等键、已接收锁定、转出方编辑作废、权限规则与双联条码打印继续保留。
- 本地预览仍为独立免登录演示，使用终端 Playwright 验证；禁止使用 Codex 内置浏览器。


## 上一版方案：深蓝侧栏与橙色操作

本节替代下方历史原型中的工单、工序和生产报工界面要求。当前业务范围以 [一期物料流转口径](phase-1-material-transfer.md) 为准。用户选定的视觉源文件为 [selected-style.png](design/selected-style.png)。

- **全局框架**：全高深蓝侧栏，白色顶栏与工作区；桌面侧栏 208px（按用户反馈收窄；窄桌面 192px）、顶栏 76px、工作区 32px 留白。侧栏、顶栏和工作区采用同一网格布局，展开时主内容同步缩窄，收起时主内容扩展。641px 以上保持联动，640px 及以下使用手机导航抽屉。转料列表按可用内容宽度调整筛选与记录布局。
- **视觉层级**：页面标题 28px，正文 14px，辅助文字至少 13px（紧凑手机元信息 12px）。4px 圆角与浅色边框，页面不叠加装饰卡片和浮动阴影。图标统一采用 Element Plus Icons。
- **颜色**：深蓝 #0b213e 为导航，橙色 #c75200 为主要操作，蓝色用于数据链接。待接收用橙色、已接收用绿色、已作废用灰色，全部伴随文字。
- **转料记录**：状态页签、单行筛选、表格和底部分页；批次入口打开详情，真实 Code 128 保留在详情及打印联。手机改为可点击记录行，保留批次、流水号、交接方向、件数、重量与状态。
- **扫码接收**：扫码输入与本次记录分区；扫码枪输入批次号后回车读取详情，再由接收方整单确认。
- **流水追踪**：完整流水号查询、最近流转摘要及按时间排列的交接记录；保留所有分页记录，不把最近一笔位置等同于全部物料库存。
- **班组和班组长管理**：相同标题、摘要、筛选、表格和表单规范，仅管理员可进入。
- **登录和访问锁**：登录页沿用深蓝品牌区和白色表单区；站点访问锁继续遵守仅显示锁图标、点击后展开口令框的要求。
- **动效**：控件反馈 120ms，页面淡入 180ms，抽屉/侧栏 240ms；刷新保持表格挂载，以加载遮罩提示；遵守减少动态效果偏好。
- **业务约束**：转出班组从登录账号确定；待接收单允许转出方编辑或作废，接收方仅整单确认；已接收永久锁定；管理员转料只读；保持接口、幂等提交与 A4 双联打印协议。
- **验收方式**：独立终端 Playwright，禁止使用 Codex 内置浏览器。截图与交互证据保存在 `output/playwright/selected-style/`，验收结论见根目录 `design-qa.md`。本地演示接口只在回环地址运行，不访问生产数据。

## 历史改版讨论（不作为一期新增业务范围）

> 状态：已确认，作为后续前端改版、测试和验收基准  
> 确认日期：2026-09-05  
> 当前业务规则以 [一期物料流转口径](phase-1-material-transfer.md) 为准，技术边界以 [前端与系统架构](frontend-architecture.md) 为准。下方旧原型仅作演进记录，不恢复已删除的业务模块。

## 1. 改版目标

- 使用 Vue 3、TypeScript、Vite、Element Plus、Pinia、Axios、ECharts 和 JsBarcode。
- 使用组件库的目的不是简单替换控件，而是获得成熟、统一、可靠的视觉与交互基础。
- 在 Element Plus 之上建立本项目自己的工业后台设计语言，不能直接呈现默认组件库皮肤。
- 最终界面应达到可直接向甲方演示和交付的商业后台水准，而不是普通表单与表格的堆砌。
- 页面首先解决生产人员的判断效率：一眼看清工单在哪里、经过哪些工序、各处有多少数量、下一步能做什么。
- 动画用于解释状态变化和确认操作结果，保持短促、稳定、克制，不能影响连续扫码和班组作业。

## 2. 整体设计方向

### 2.1 视觉气质

- 成熟、稳重、清晰、专业、高效。
- 深灰蓝侧边栏、浅灰页面背景、白色主要内容面板。
- 蓝色作为主操作色；绿色表示正常或完成；橙色表示待处理；红色表示异常、丢料和转废。
- 不使用廉价的大面积渐变、发光描边、过度阴影和无意义的大圆角。
- 保持合理的信息密度，桌面端优先展示生产数据，不使用大量空白制造“高级感”。
- 优先适配 1920×1080 和 1366×768 工厂电脑，同时保证平板和手机可完成查看及扫码操作。

### 2.2 设计变量

- 在全局集中定义颜色、字号、行高、圆角、阴影、间距、层级和动画时长。
- 使用 4px/8px 间距体系，统一页面、卡片、表单、表格和弹窗的留白。
- 页面标题、模块标题、正文、辅助信息和关键数字形成清晰层级。
- 工单号、当前班组、当前工序、在制数量和异常数量必须比次要字段更醒目。
- 时间统一到分钟，格式为 `YYYY-MM-DD HH:mm`。
- 所有状态使用同一套名称、颜色和图标，不允许各页面自行创造近义状态。

### 2.3 状态规范

至少统一覆盖：

- 待生产
- 生产中
- 待接收
- 部分流转
- 已完成
- 已发货
- 异常
- 丢料
- 失败
- 转废

状态不能只靠颜色区分，还要同时显示文字或图标，确保可读性和无障碍性。

## 3. 前端工程要求

### 3.1 目录职责

- `api` 或 `services`：全部接口请求、协议转换和错误归一化。
- `stores`：访问锁、登录用户、权限、班组目录、全局反馈和必要的跨页面状态。
- `views` 或 `pages`：路由级业务页面。
- `components`：可复用业务组件和基础展示组件。
- `layouts`：访问口令、登录和后台主框架。
- `composables`：扫码监听、分页、筛选、权限判断和表格尺寸等复用逻辑。
- `styles`：设计变量、Element Plus 主题覆盖、公共布局和动画。
- `utils`：时间、数量、状态和错误信息格式化。

### 3.2 Axios

- 使用统一 Axios 实例管理基础地址、超时、认证信息和响应格式。
- 统一处理登录失效、访问口令失效、无权限、网络中断、请求超时和业务错误。
- 防止重复提交；页面切换后取消已经没有意义的查询请求。
- 页面不得自行拼接重复的错误提示，也不得直接依赖后端原始错误结构。

### 3.3 Pinia

- 只保存跨路由或跨组件共享的状态，不把所有接口响应都塞入全局 store。
- 访问锁、用户会话、角色、账号绑定班组和动态班组目录要有明确 store。
- 退出登录、访问锁过期或切换账号时必须清除相应敏感状态。
- 页面内筛选、弹窗开关和表单草稿默认保留在页面组件中。

### 3.4 ECharts 与条形码

- 图表按需加载，具有加载、空数据、失败和自适应状态。
- 图表首次加载和数据更新采用平滑但克制的动画。
- 条形码使用 Code 128，编码值固定等于一次实际转料的转料批次号。
- 不使用二维码；每次实际转料生成独立批次号和对应条形码，工单号与流水号不作为转料条码。

## 4. 后台整体框架

### 4.1 侧边栏

建议导航层级：

- 工作台
- 工单管理
- 流水号物料追踪
- 转料批次
- 流转记录
- 班组生产
  - 扎板
  - 退火
  - 研磨
  - 线切割
  - 雕刻
  - 电镀
  - 检验
  - 发货
  - 转废
- 基础设置
  - 产品管理
  - 工艺管理
  - 班组管理
  - 账号管理
  - 异常原因
- 系统记录
  - 主系统接口台账
  - 出入库对账

详细要求：

- 班组菜单由后台班组资料动态生成，不能写死；管理员新增、排序、停用班组后同步更新。
- 班组账号优先看到自己的班组，管理员可以看到全部班组。
- 当前页面高亮明确，分组层级清楚，避免重复入口和过长菜单。
- 支持展开、收起和滚动；收起后保留图标与悬浮提示。
- 侧边栏展开/收起过程平滑，不得造成内容区明显跳动。
- 基础设置只向管理员展示；前端隐藏不能代替后端权限校验。

### 4.2 顶部区域

- 显示页面标题和面包屑。
- 显示当前账号、角色及绑定班组。
- 提供退出登录和必要的账号菜单。
- 显示全局扫码监听状态及网络异常提示。
- 不堆放低频按钮，页面级主操作保留在页面标题区。

## 5. 访问口令与登录

### 5.1 访问口令页

- 使用极简空白浅色页面，中央只保留锁图标、口令输入框和提交动作。
- 不放系统介绍、宣传内容、数据卡片和复杂装饰。
- 支持回车提交；提交中显示加载状态。
- 输错后显示简短、明确的错误，并使用轻微抖动反馈。
- 访问口令由部署管理员配置并通过安全渠道提供，前端不得把正确口令写死在可读取的源代码中。

### 5.2 登录页

- 简洁、专业，不使用廉价渐变背景。
- 账号和密码输入框、按钮和错误状态统一。
- 支持回车登录、密码显示/隐藏和提交防重复。
- 登录失败说明具体原因；登录成功后自然过渡到原目标页面。
- 已登录用户不重复进入登录页；会话失效后保留安全的站内返回地址。

## 6. 工作台

工作台需要回答“现在工件在哪里、生产是否正常”。至少展示：

- 工单总数、生产中、待接收、今日完成、异常和转废数量。
- 各班组当前工单数和在制数量。
- 最近流转记录和需要处理的异常工单。
- 生产趋势图和各班组产量对比图。
- 快速扫码入口或全局扫码状态。

图表要求：

- 首次加载渐入，数据变化平滑过渡。
- 悬停显示准确数值和单位。
- 颜色与全局状态规范一致。
- 无数据时显示可理解的空状态，不显示空白坐标系。
- 容器尺寸变化时自动重绘，不产生文字遮挡。

## 7. 工单管理

### 7.1 工单列表

直接显示：

- 工单号和从公司主系统取得的流水号。
- 产品、计划数量、当前班组、当前工序和当前状态。
- 已完成、在制、异常、丢料和转废数量。
- 下单时间、最后操作时间和操作入口。

支持：

- 按工单号、流水号、转料批次号、产品、班组、工序、状态和时间范围筛选。
- 组合筛选、重置、分页、排序和导出。
- 点击整行查看详情；操作按钮不得挤占过多表格宽度。
- 扫描转料批次号并回车后留在当前页面，以抽屉或弹层打开本次转料摘要。
- 1366×768 下关键列和主操作仍然可见，次要信息可折叠或进入详情。

### 7.2 新建和编辑工单

字段至少包括：

- 工单号
- 流水号或公司主系统工件信息导入入口
- 产品
- 计划数量
- 交付日期
- 对应工艺
- 初始班组
- 备注

交互要求：

- 选择产品和工艺后，直观展示完整有序工艺路线。
- 每道工序明确展示上序、当前工序、下序和负责班组。
- 提供实时校验、错误字段定位、重复提交防护和未保存离开提醒。
- 保存成功后直接进入新工单详情，不要求用户重新搜索。

## 8. 工单详情与全生命周期流转

这是核心页面，必须展示一张工单从下单到结束的整体状态，而不是只显示最新一次转序。

### 8.1 头部摘要

- 工单号、流水号和公司主系统出入库状态；工单头不再展示工单号条形码。
- 产品、计划数量、当前班组、当前工序、上序和下序。
- 当前状态、累计完成、在制、异常、丢料和转废数量。
- 首次打印、最近打印和最后操作时间，精确到分钟。

### 8.2 工艺进度

- 使用步骤条或流程轨道展示完整工艺路线。
- 区分已完成、当前、未开始、异常、跳过和转废状态。
- 点击工序可查看该工序的报工、接收、损耗和操作人员。

### 8.3 分批流转明细

同一工单允许多次分批提交下序。每批至少显示：

- 来源班组、目标班组、批次数量和合格数量。
- 转废、丢料和剩余可接收数量。
- 提交人、接收人、提交时间和接收时间。
- 原因、备注和当前批次状态。
- 每次实际转料的持久化批次号及对应 Code 128 条形码。

例如 1000 件可以先流转 400 件，再流转 350 件，剩余 250 件继续留在上序；其中发生的转废或丢料必须独立追溯。

### 8.4 全生命周期时间线

按时间顺序显示：

- 创建工单
- 工艺单打印与补打
- 开始生产
- 分批报工
- 下序接收
- 退回或异常
- 丢料
- 加工失败
- 转废
- 检验完成
- 发货
- 工单结束

点击每条记录可以展开数量、操作者、所属班组、原因和时间等完整细节。

## 9. 扫码交互

蓝牙扫码枪按 HID 键盘处理，即输入转料批次号字符并发送回车。

- 前端无需连接蓝牙、摄像头或厂商 SDK。
- 页面打开后即可监听扫码，不要求操作员反复点击输入框。
- 需要区分快速扫码输入和普通键盘操作，减少误触发。
- 扫码成功提供声音、颜色和短提示；失败时说明未找到、无权限或状态不允许。
- 防止同一次扫描产生多个弹窗或重复提交。
- 扫码后优先打开右侧详情抽屉，并保持用户仍在原业务页面。
- 抽屉内显示批次号、流水号、来源、去向、物料类型、数量、重量、接收进度和当前账号允许的主操作。
- 支持继续扫描下一张转料单，抽屉内容平滑替换，不需要刷新页面。

## 10. 班组生产页面

每个班组页面展示：

- 待接收、正在生产、待流转的工单。
- 今日接收、今日完成、异常、丢料和转废数量。
- 每张工单在本班组的已收、已加工、已转和剩余数量。
- 本班组近期产量趋势和需要处理的异常。

权限与入口：

- 班组账号默认且只能对绑定班组执行录入操作。
- 管理员可进入具体班组代操作，但仍受数量和状态规则约束。
- 转废班组显示报废台账，不作为正常工艺报工入口。

主操作包括：

- 接收上序来料
- 开始加工
- 分批提交下序
- 登记异常
- 登记丢料
- 登记失败
- 转废
- 查看完整流转

高频主操作直接突出，低频操作收进“更多”，避免一行塞满按钮。

## 11. 分批流转表单

提交下序时显示：

- 工单计划数量。
- 当前班组已接收、已加工、已提交和剩余可流转数量。
- 本次提交数量和目标下序班组。
- 提交后预计剩余数量。
- 原因或备注。

数量校验：

- 不能小于等于零，特殊的全损耗批按既有业务规则处理。
- 不能超过当前可用数量。
- 异常、丢料和转废不能导致台账出现负数。
- 提交前展示数量变化预览，提交后以服务器返回结果刷新完整台账。

## 12. 异常、丢料、失败和转废

统一使用原因登记组件，字段包括：

- 业务类型
- 数量
- 标准原因
- 详细说明
- 操作人和所属班组
- 发生时间
- 图片或附件的后续扩展入口

管理员可以维护常用原因，例如加工失败、尺寸不合格、表面损伤、原料缺陷、设备故障、丢失、盘点差异、检验不合格、客户取消和其他。

- 转废使用明确的红色危险状态和一次有效确认。
- 不连续弹出多层确认框。
- 登记完成后，工单摘要、班组台账和时间线同时更新。

## 13. 班组产量

按班组展示：

- 今日、本周和本月产量。
- 合格、异常、转废、丢料和当前在制数量。
- 各工单产量及按日期的变化趋势。

支持：

- 选择班组和时间范围。
- 管理员查看全部班组汇总，班组账号默认查看自己班组。
- 从图表或表格进入具体工单详情。
- 图表和表格使用同一筛选条件并同步更新。
- 清楚区分“班组累计加工量”和“整单最终完成量”，避免重复汇总。

## 14. 产品与工艺管理

管理员可以：

- 创建产品及版本化工艺路线。
- 添加工序、选择负责班组、拖动调整顺序。
- 直观看到每一步的上序和下序。
- 复制已有工艺、停用旧工艺，并查看正在使用的产品。
- 删除或调整时显示影响范围，不能破坏已下达工单的工序快照。

工艺编排需要使用可视化步骤列表或流程轨道，不能只提供一张难以理解的普通表格。

## 15. 班组、账号与原因设置

### 15.1 班组管理

- 新增班组、修改名称、排序、颜色和图标。
- 停用班组并查看其历史数据影响。
- 查看班组成员和当前工单数量。
- 保存成功后刷新动态侧边栏和相关选择器。

### 15.2 账号管理

- 创建管理员账号或班组账号。
- 班组账号必须绑定一个有效班组；管理员可以不绑定班组。
- 支持重置密码、停用账号和修改所属班组。
- 列表清楚展示账号角色、班组、状态和最后活动信息。

### 15.3 异常原因

- 管理员维护原因名称、适用类型、排序和启停状态。
- 业务表单优先选择标准原因，同时允许填写详细说明。

## 16. 打印与条形码

工艺单打印预览至少包括工单号、流水号、产品、计划数量、工艺路线和备注。转料单打印预览至少包括：

- 转料批次号及其 Code 128 条形码。
- 工单号、流水号和产品信息。
- 物料类型、本工序、下工序、转料数量和转料重量。
- 转料人、接料人和备注。
- 打印时间，精确到分钟。

支持单张打印、批量打印、份数调整和打印前预览。条形码下方必须保留可读转料批次号，并使用真实打印尺寸验证普通扫码枪识别效果。

## 17. 公共业务组件

需要逐步沉淀以下复用组件：

- 页面标题与主操作区
- 统一筛选栏
- 工单状态标签
- 数量台账摘要
- 转料批次 Code 128 条形码卡片
- 转料批次扫码详情抽屉
- 工艺流程步骤条
- 全生命周期时间线
- 分批流转表格
- 原因登记弹窗
- 扫码监听与扫码状态提示
- 空状态、无权限、加载失败和重试组件
- 表格骨架屏与提交按钮状态

同一业务行为必须复用同一交互组件，避免不同页面出现不同文案、布局和确认方式。

## 18. 动画与操作反馈

统一实现：

- 页面切换淡入。
- 抽屉平滑滑入。
- 弹窗轻微缩放进入。
- 表格行和卡片悬停反馈。
- 按钮按下和提交中反馈。
- 状态与数字更新过渡。
- 扫码成功高亮。
- 错误输入轻微抖动。
- 图表加载和数据更新动画。
- 侧边栏展开和收起动画。

标准：

- 常规动画时长控制在约 160～240ms。
- 不阻塞点击、扫码或连续录入。
- 遵循 `prefers-reduced-motion`，用户减少动态效果时关闭非必要动画。
- 禁止大幅弹跳、长时间旋转、粒子背景和纯装饰性动画。

## 19. 加载、空状态和错误处理

所有页面补齐：

- 初次加载骨架屏。
- 表格局部加载状态。
- 无数据和筛选无结果状态。
- 无权限状态。
- 网络断开、请求超时和服务异常状态。
- 成功、失败和部分成功提示。
- 重试入口、提交防重复和危险操作确认。
- 合理保留筛选条件及分页位置。

禁止出现：

- 点击后没有反馈。
- 加载时整页空白。
- 页面刷新或弹窗打开时明显跳动。
- 错误信息只有笼统的“请求失败”。
- 同一种操作在不同页面使用不同名称或完全不同交互。

## 20. 响应式与可用性

- 1920×1080 和 1366×768 桌面端作为主要验收尺寸。
- 窄桌面优先保留工单号、状态、位置、数量和主操作，次要列进入展开详情。
- 手机端把宽表格转换为工单卡片或详情抽屉，不做简单横向压缩。
- 表单标签、点击区域、键盘焦点和错误提示清晰可见。
- 支持键盘回车提交、扫码枪输入和合理的焦点恢复。
- 颜色对比、状态文字、图标替代文本和减少动画模式满足基本无障碍要求。

## 21. 权限表现

- 管理员查看和维护全部业务及基础资料。
- 班组账号只显示与绑定班组相关的业务入口和允许操作。
- 无权限按钮不展示；直接访问无权限地址时显示统一无权限页面。
- 登录过期后安全地返回登录页，重新登录后回到原页面。
- 访问口令失效时先返回锁页面。
- 前端权限只改善交互，所有关键权限、状态和数量仍由后端复核。

## 22. 性能要求

- 路由页面、ECharts 和低频管理模块按需加载。
- 避免重复查询班组目录和工单详情。
- 搜索输入进行防抖，筛选变化避免并发旧请求覆盖新结果。
- 大表格保持分页；暂不一次渲染全部工单和流转记录。
- 条形码和图表在离开页面后正确释放资源。
- 生产构建无 TypeScript 错误、明显控制台错误或失效资源请求。

## 25. 大循环与小循环新增页面

本节按 [物料系统大小循环与编号需求](material-system-requirements.md) 扩展前端范围。

### 25.1 流水号物料追踪

- 输入流水号后从公司主系统读取并展示订单或工件基本信息。
- 显示产品、客户、材质、规格、技术要求、计划数量及外部单据状态。
- 按工序汇总当前持有、加工中、待转、在途、已接收、异常和待公司入库的数量与重量。
- 展示该流水号下的全部转料批次，支持从批次进入本次转料详情。
- 明确区分工单号、流水号、转料批次号和公司主系统单据号。

### 25.2 转料批次列表与详情

- 列表按批次号、流水号、工单号、来源、去向、物料类型、状态和时间筛选。
- 每行显示批次条形码、转料数量与重量、已收与待收、转料人和转料时间。
- 批次详情展示公司主信息快照、上序、下序、批次明细、扫码接收、异常、打印和完整审计记录。
- 批次首次被下序接收后，修改和删除入口立即锁定，并明确说明锁定原因。
- 批次条形码是扫码入口；工单号与流水号只作为查询条件和上下文信息。

### 25.3 公司主系统接口台账

- 仅管理员可见，展示外部出库、外部入库及流水号查询记录。
- 显示外部单据号、方向、业务对象、数量、重量、同步状态、请求时间、确认时间和失败原因。
- 支持查看失败详情、按权限重试和人工标记待对账，不能允许普通班组账号修改同步结果。
- 用明确状态区分待同步、同步中、成功、失败和待人工处理。
- 页面不得展示接口密钥、令牌或包含敏感信息的完整原始请求。

### 25.4 大小循环总览

- 工单详情顶部增加大循环状态：主系统待出库、已出库、车间加工中、车间已完工待入库、主系统已入库或接口异常。
- 小循环时间线集中展示本系统内每次转料批次和上下序接收。
- 大循环事件和小循环事件使用不同视觉层级，但按真实时间顺序保持完整追溯。
- 车间完工不等于公司主系统已入库，页面必须分别显示两种状态和数量。
