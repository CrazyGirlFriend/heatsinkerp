# 废泥折算重量

## 业务口径

`折算重量 = 废泥实重 × 有效材料占比 / 100`。占比不是含水率。

例如 10 kg 废泥、有效材料占比 30%，原流水号转出 3 kg 材料，签收后库房增加 3 kg 废泥材料库存，同时保留 10 kg 实重。再次转出时仍按原占比，不把 3 kg 再乘 30%。内部转料不增加全厂投入。

## 接口

转料新建/修改、库存批量出库的每行、库房入库（含主系统快照入库）及初始库存行增加：

| 字段 | 含义 | 约束 |
|---|---|---|
| `sludge_gross_weight` | 本次废泥实重 kg | 大于 0，最多 3 位小数 |
| `sludge_content_percent` | 有效材料占比 % | 大于 0 且不超过 100，最多 2 位小数 |
| `weight` | 折算材料重量 kg，复用原字段 | 必须等于上述公式，十进制 HALF_UP 到 3 位小数，至少 0.001 kg |

例：`{"material_type":"sludge","quantity":0,"sludge_gross_weight":10,"sludge_content_percent":30,"weight":3}`。

新废泥两项测量字段必填，普通物料不能携带非空测量字段。客户端自动计算，后端独立核对；不信任客户端传来的 `weight`。单批详情返回测量字段及 `sludge_percent_locked`；后者表示来源已是有比例的废泥，后续必须沿用该比例。库存批次返回 `sludge_available_gross_weight`，供“全部填入”使用，不能反推原实重而放大舍入误差。

下游不能修改上游单据。转出待签收占用可转余额；新增、修改、作废和接收仍经过原事务、来源锁、幂等与余额维护。批量提交按来源合计校验有效重量和实重，任一行无效整笔不提交。原废泥不能通过改类型或改比例增加材料余额。

废泥丢失仍使用原丢失接口的 `weight`，单位为折算 kg。可转实重由原实重减去有效出库实重、再减去丢失折算重量按原比例换算的实重得到；不新增一套可手工编辑的余额表。单次折算有 0.001 kg 精度限制，分批舍入导致超过材料余额时仍阻止提交，不自动产生损耗或库存差额。

## 仅按重量计量（2026-10-09）

废泥、废屑只录重量，不提供件数输入；废品和废料保留件数。新建手工入库、初始库存、转料、批量出库、转投、丢失均发送 `quantity: 0`，后台独立检查件数为零、重量大于零。废泥仍保留实重与有效材料占比，不改变现有折算公式。

从普通物料切换到废泥或废屑时，不提交隐藏的旧件数，也不自动清零来源的件数；来源余数仍通过明确勾选的清零操作记录。禁止对废泥、废屑新增加工件数变更。历史记录不迁移或重算，历史单据中已有件数在编辑其他内容时原样保留，不能借此增加件数。
