# 库房来源与物料性质

状态：来源分组明细、废屑出入库查询及独立批次已随 `6fdf069` / `20260918T045500Z` 部署。原来源分类于 2026-09-16 上线，详见 [服务器部署记录](server-deployment.md)。后续 [八班组分类库存明细](team-classified-inventory.md) 已随 `20260918T064256Z` 发布。

## 使用方式

库房仍是一个班组，不新增废料班组。两个维度分别记录：

| 维度 | 记录内容 | 操作入口 |
| --- | --- | --- |
| 来源 | 外部来料、外部退回、车间转入 | 库房入库记录按来源筛选 |
| 物料性质 | 原材料、半成品、成品、成品余料、半成品余料、废品、废料、废泥、废屑 | 入库/转料逐条选择，详情及纸质单据保留 |

- 外部来料：库房“新建入库”，填写来源单位、流水号、物料性质及件数/重量；确认后入账并锁定。
- 外部退回：在手工入库中选择“外部退回”，沿用原流水号，可关联已确认的出库/发货批次号（历史 CK 兼容）。关联时校验该流水号的已确认对外出库记录；不要求修改主系统流水号资料。
- 车间转入：上序填写本次转料性质，库房在“待接收”核对整批确认。已接收记录自动归入同一个“入库记录”页面；不再重复手工入库。
- 同一来源同时有半成品和废料：出库时点击“拆分物料”，分别填写两行件数、重量和性质。合计不能超过来源余量，每行各有独立批次号、条码和接收状态，可合并打印。
- 库房库存按流水号归组，同一流水号的材质、规格、物料类型、来源不同则分行；相同来源的多次入库合并余额，原始批次放在“明细”。后续已发布版本已将该规则统一到其他七班组，来源显示上序班组。
- “统计 → 材质归类”分别展示正常可用、废料结存，并提供按物料性质的结存表；“统计 → 数据分析”保留原分析图表。

## 库房库存明细（2026-09-17）

- 默认八列：流水号、材质、规格、物料类型、来源、当前件数、当前重量、操作。相邻同流水号、同材质单元格合并，不重复铺卡片。
- 来源分为外部来料、外部退回、车间转入，并显示对应单位或来源班组。历史空来源显示“未登记”，不根据备注推测。
- 默认包含所有有实物结存的正常物料和废料；废屑只有重量、件数为零也显示。已出完记录在“更多 → 库存范围 → 全部（含已出完）”查看。
- 按来源、类型筛选后，数量和重量只计算匹配分组，不混入同流水号的其他来源。每页默认 10 条库存明细，可选 20/50/100 条；同流水号跨页时重新显示标识。
- 点击“明细”查看该来源与类型的全部入库批次（含已出完）；点击“出库”仅选择该分组仍有余额的批次。顶部“新建出库”仍支持全库选料、多流水号整批出库。
- 点击流水号仍能查看该流水号完整的来源余额、转入、转出及丢失历史；管理员在流水号下方标记加急，不能代替班组办理出入库。
- 保留自选字段、字段查询、数值比较和搜索字段临时首列。新页面列配置独立按账号/班组保存，不覆盖其他班组设置；资料冲突显示“多值”，具体值在原单核对。
- “流转日期”筛选该分组在日期内发生过接收、转出或丢失的记录，但余额始终是当前余额，不是历史快照。实时推送更新列表并保留未提交的搜索输入。
- 待接收徽标按实际独立批次计数；未接收物料不进入库存。
- 废屑出入库均可在对应记录页选择“物料类型 → 废屑”，叠加日期、状态或关键词查询。出库逐批展示，只统计匹配类型的件数、重量；已经出完和只有重量的批次也可查询。

### 只读查询接口

- `GET /api/team-materials/{team_id}/warehouse-inventory`：仅正式库房；分页在分组求和之后执行。参数包括 `query`、`search_field`、`search_operator`、`receipt_source=external|return|internal`、`source_team_id`、`material_type`、`availability=current|available|scrap|all`、日期及分页。
- `GET /api/team-materials/{team_id}/warehouse-inventory/{group_id}/sources`：按所选分组查询原始已接收批次；`current_only=true` 仅保留出库可选来源。`group_id` 是该组最早入库记录的 ID，不是新增单号。
- 新查询不落重复库存表、不新增数据库迁移；直接复用收发与丢失余额查询。仍需应用原来源分类迁移 `20260916_0013`。

历史外部来源未填写的，显示“外部来源未登记”；不会根据备注猜测来源。为兼容历史调用和待联调主系统，普通外部入库 API 仍允许来源单位为空；新手工表单要求填写，外部退回 API 也要求填写。

## 库存口径

- 当前库存包含废料；内部转料、库房对外出库及检验发货均在提交时扣减，只有内部转料在下序确认前计入在途。
- 正常可用库存不包含废品、废料、废泥、废屑；成品余料、半成品余料仍属于正常物料，不自动判废。
- 废料对外处理提交时即扣减废料结存与可处理余量，待确认量单列；确认不重复扣减，未确认单作废返还废料库存。
- 废料只允许转入库房或由正式库房办理对外处理，须填原因和外部去向。不能通过修改物料类型把已入账废料变成正常可用库存，也不能按检验成品发货。
- 同流水号的分类落在各次入库/转料明细上，不修改整个流水号的统一性质。列表、统计及大屏继续从实际收发记录计算并实时推送。
- 首页“全厂在库”仍是实物总量，含废料，不等于正常可用库存。

## 库房退回核对

单条详情，或整批单中展开某行详情后，可选择“退回核对”填写原因。仅接收库房可操作；管理员只读。

退回核对不是实物退料，不作废单据、不恢复上序库存。物料保留在途、占用来源余量。上序实际修改该批次后才能接收；无变化的保存不会解除限制。不影响合印在同一纸上的其他批次。修改、退回和最终确认均保留审计记录。实物未转出且需取消时，由上序按既有作废操作处理。

## 发布注意

- 新增迁移 `20260916_0013`，仅添加四个可空字段：`receipt_kind`、`external_source`、`return_dispatch_no`、`rejection_reason`。保留旧数据，不清空、不推测分类；新代码须在迁移后启动。
- 后端新增退回核对接口 `POST /api/material-transfers/{batch_no}/reject`，请求为 `expected_version` 和 `reason`。
- 入库查询新增 `receipt_source=external|internal|return`（external 含退回）；库存选料支持 `availability=dispatchable`；流水号列表支持 `availability=scrap`，并允许搜索 `scrap_quantity`、`scrap_weight`。
- 物料类型增加 `raw_material`；主系统公开 JSON Schema / OpenAPI 已同步。主系统仍未启用，本次不新增对外调用。
- 新迁移不提供删除字段的降级操作，避免丢失来源与核对记录。上线前按现有部署说明备份数据库。
